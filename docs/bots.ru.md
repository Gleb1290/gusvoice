# Боты GusVoice (Bot API v1)

> English version: [bots.md](bots.md) · Для нейронок: [bots-llm.md](bots-llm.md) · Как сделать бота с помощью нейронки: [bots-playbook.ru.md](bots-playbook.ru.md)

Бот — это аккаунт, которым управляет **программа**, а не человек. У бота есть ник, имя, аватар и значок **БОТ**; с ним
можно переписываться в личных сообщениях. Программа входит по **токену**, получает сообщения людей и отвечает на них —
через обычные HTTP-запросы (`curl`, Python, Node, что угодно).

Типичные применения: уведомления себе (диск заполнился, сборка упала), панель управления сервером (`/status`,
`/restart nginx`), напоминалки, ответы на команды.

Интерфейс GusVoice русский, названия кнопок ниже даны так, как они в приложении.

**Что в этой версии (API 4).** Боты работают в **личных сообщениях** (беседа 1:1 «человек — бот») с меню команд по `/` и
кнопками под сообщением, **на серверах** (каналы, приватность как в Telegram, реакции, модерация — раздел «Боты на серверах»)
и **в голосовых каналах** (бот играет звук — раздел «Голос»). Групповых бесед и федерации для ботов нет.
См. [Отличия от Telegram](#отличия-от-telegram).

## Боты и вебхуки — в чём разница

| | Входящий вебхук ([webhooks.ru.md](webhooks.ru.md)) | Бот |
|---|---|---|
| Что это | Секретный адрес, **только писать** в текстовый канал | Аккаунт с токеном: получает сообщения **и** отвечает |
| Куда пишет | В канал сервера | В личную беседу с человеком |
| Читает ли сообщения | Нет | Да — те, что написаны ему в личные |
| Вход | Токен в адресе | Заголовок `Authorization: Bot <токен>` |
| Профиль, ник, «написать в личные» | Нет | Есть |
| Кто заводит | Тот, у кого есть право «Управление вебхуками» | Любой человек, если администратор инстанса разрешил |

Нужно просто «выплюнуть» уведомление в канал — берите вебхук. Нужен диалог или команды — бот.

## Как включить (администратор инстанса)

По умолчанию боты на инстансе **выключены**: токены не принимаются, создать бота нельзя. Включает супер-администратор,
файлы на сервере править не нужно.

**Админ-панель → «Боты»:**

- **«Боты на этом сервере»** — главный тумблер. Выключение сразу гасит всех ботов: токены перестают приниматься
  (`403`), открытые WebSocket закрываются, события не копятся. Настройки и сами боты сохраняются.
- **«Кто может создавать ботов»**: «Все», «Только одобренные» (аккаунт одобрен администратором), «Только администратор».
- **«Сколько ботов может быть у одного человека»** — от 0 до 100, по умолчанию 10. Администратора лимит не ограничивает.
  Кроме того, один человек может создать не больше 10 ботов в час.
- **«Разрешить доставку на внутренние адреса»** — по умолчанию выключено (см. [SSRF](#защита-от-ssrf)).
- **«Все боты»** — таблица всех ботов с владельцами: выключить бота (токен перестаёт приниматься, WebSocket закрывается),
  включить обратно, удалить.

Боты живут только на своём инстансе: они не попадают в каталоги соседних инстансов (федерация) и не пишут людям с других
инстансов.

## Быстрый старт за 5 минут

Нужны: инстанс с включёнными ботами и `curl`. Адрес API вашего инстанса ниже — `https://chat.example.com` (подставьте
свой; это адрес API, как и в адресах вебхуков).

1. **Создайте бота.** Настройки → **«Мои боты»** → «Создать бота». Ник — латиница, цифры и `_`, 3–32 знака,
   **обязательно оканчивается на `bot`** (как в Telegram), например `vps_alert_bot`. Имя и описание можно поменять позже.
2. **Скопируйте токен.** Он показывается **один раз** (на сервере хранится только хеш). Потеряли — «Перевыпустить токен»:
   новый выдаётся сразу, старый перестаёт работать. Токен выглядит как `gvb_…` (4 знака префикса + 43 знака).
3. **Откройте беседу с ботом** — кнопка «Открыть беседу». Новый бот **приватный**: писать ему может только владелец.
   В пустой беседе по центру кнопка **«Старт»**, поле ввода появится после нажатия. «Старт» отправляет сообщение `/start`.
4. **Проверьте токен и заберите сообщение:**

```sh
export GV_API=https://chat.example.com/api/bot/v1
export GV_TOKEN=gvb_...                      # токен из шага 2

curl -sS "$GV_API/getMe" -H "Authorization: Bot $GV_TOKEN"
# {"ok":true,"result":{"id":"…","username":"vps_alert_bot","display_name":"…","bot":true,"description":"","about":"","public":false}}

curl -sS "$GV_API/getUpdates?timeout=10" -H "Authorization: Bot $GV_TOKEN"
# {"ok":true,"result":[
#   {"update_id":101,"my_chat_member":{"chat":{"id":"<chat_id>","type":"dm"},"from":{…},"date":…,"old_status":"left","new_status":"member"}},
#   {"update_id":102,"message":{"message_id":"…","chat":{"id":"<chat_id>","type":"dm"},"from":{"id":"<ваш id>",…},"date":…,"text":"/start"}}
# ]}
```

5. **Ответьте** (подставьте `chat.id` из события):

```sh
curl -sS "$GV_API/sendMessage" -H "Authorization: Bot $GV_TOKEN" \
  -d chat_id=<chat_id> -d "text=Привет! Диск / заполнен на 91%"
```

Сообщение появится в беседе. Чтобы события не приходили повторно, подтвердите их: следующий запрос
`getUpdates?offset=103` (последний `update_id` + 1) — всё, что меньше, считается принятым. Подробности — в
[справочнике](#справочник).

> Бот **не может написать первым**: беседу с ним открывает человек (кнопка «Открыть беседу», поиск, «Написать»).
> Пока беседы нет, `sendMessage` отвечает `400 chat not found`.

## Справочник

### Вызов

```
GET|POST https://chat.example.com/api/bot/v1/<метод>
Authorization: Bot <токен>
```

- Имя метода не зависит от регистра (`getMe` = `getme`). Любой метод можно вызвать и `GET`, и `POST`.
- Параметры можно передать **любым** способом (как у Telegram): JSON-телом (`Content-Type: application/json`), формой
  (`application/x-www-form-urlencoded`, удобно для `curl -d`), `multipart/form-data` или строкой запроса. Если один и тот же
  параметр пришёл и в строке запроса, и в теле, побеждает тело.
- Из формы и строки запроса числа и флаги принимаются строкой (`limit=50`, `disable_notification=true` или `=1`);
  массивы и объекты (`allowed_updates`, `embeds`) — строкой JSON.
- **Идентификаторы** — строки (UUID): `chat_id`, `message_id`, `from.id` всегда строки, даже если выглядят как числа
  в другом API. Число вместо строки — `400`. **Время** — секунды Unix (целое). Поля — `snake_case`.
- Лишние неизвестные параметры игнорируются.
- Тело JSON/формы — до **64 КБ**. Файлы — только `multipart` и только у `sendMessage`.
- Токен — **только** в заголовке `Authorization: Bot <токен>`. `Bearer` (токен людей) и токен в адресе не принимаются.

### Ответ и ошибки

Успех — HTTP 200:

```json
{ "ok": true, "result": <значение> }
```

Ошибка — HTTP-статус равен `error_code`:

```json
{ "ok": false, "error_code": 429, "description": "Too Many Requests: retry after 3", "retry_after": 3 }
```

`retry_after` (целые секунды) и заголовок `Retry-After` есть только у `429`. **Ветвитесь по `error_code`**, а не по
тексту `description`: текст человеческий, местами на русском, и может меняться.

| `error_code` | Когда |
|---|---|
| 400 | Неверный параметр (в `description` — какой: `Bad Request: chat_id: …`); беседа не найдена или не ваша (`chat not found`); сообщение не найдено; пустое сообщение; ответ на несуществующее сообщение; кривой адрес доставки; файлы не в `files[n]`; файлы не у `sendMessage`; тело больше 64 КБ |
| 401 | `Unauthorized` — нет заголовка, не схема `Bot`, токен не подходит (в том числе перевыпущен), бот выключен администратором |
| 403 | Боты выключены на инстансе; собеседник заблокировал бота; собеседник удалил аккаунт |
| 404 | Нет такого метода (проверяется после токена: без токена методы не раскрываются) |
| 409 | `getUpdates`, пока задан адрес доставки; ждущий `getUpdates`, который сменил другой потребитель (`Conflict: terminated by other getUpdates request; make sure that only one bot instance is running`) |
| 415 | Файл запрещённого типа (SVG, HTML) |
| 429 | Предел частоты (см. [Пределы](#пределы)) |
| 500 | Внутренняя ошибка сервера |
| 503 | Хранилище файлов не готово (при отправке файла) |

### Объекты

В будущих версиях в ответах могут появиться новые поля — незнакомые спокойно пропускайте. Id — строки (UUID), время — секунды Unix.

#### Attachment

Файл, приложенный к сообщению.

| Поле | Тип | |
|---|---|---|
| `url` | string | ссылка именно **для вашего бота**, скачивается обычным `GET` без заголовков; не публикуйте её. Работает, пока у бота есть доступ к беседе |
| `file_name` | string | имя файла |
| `mime_type` | string | тип файла |
| `file_size` | number | размер в байтах |

#### BotCommand

Команда в подсказке, которую человек видит, набрав `/`, например `{ "command": "status", "description": "Состояние сервера" }`.

| Поле | Тип | |
|---|---|---|
| `command` | string | имя без косой черты (шаблон `^[a-z0-9_]{1,32}$`) |
| `description` | string | что делает (1–256 знаков) |

#### BotCommandScope

Где действует список команд.

| Поле | Тип | |
|---|---|---|
| `type` | string | `default`, `all_private_chats` (личные) или `all_group_chats` (серверы). Другие типы → `400`. В личных берётся `all_private_chats`, если задан, иначе `default`; на серверах — `all_group_chats`, иначе `default` (≤ 32 знаков) |

#### BotUser

Сам бот (ответ `getMe`): [User](#user) плюс профиль бота и что умеет сервер. Нужное проверяйте по `features`, а не по версии; сервер постарше не присылает `api_version`/`features`.

| Поле | Тип | |
|---|---|---|
| `id` | string | id бота |
| `username` | string | ник бота |
| `display_name` | string | имя; если не задано — ник |
| `bot` | boolean | всегда `true` |
| `instance_domain` | string, необязательно | есть у гостей с других инстансов (федерация); ники могут совпасть с местными — проверяйте по `id` |
| `description` | string | описание (до 512 знаков) |
| `about` | string | коротко «о боте» (до 120 знаков) |
| `public` | boolean | можно ли писать боту всем |
| `api_version` | number, необязательно | версия Bot API сервера: 2 — кнопки и команды, 3 — серверы, 4 — голос |
| `features` | массив string, необязательно | что умеет сервер: `polling`, `ws`, `webhook`, `keyboards`, `commands`, `client_id`, `servers`, `reactions`, `parse_mode`, `webhook_batch`, `voice`, …; новые дописываются в конец |
| `dropped_update_count` | number, необязательно | сколько событий срезал потолок журнала (есть, если срезал) |

#### CallbackQuery

Нажата кнопка с `callback_data`. Ответьте на неё `answerCallbackQuery`.

| Поле | Тип | |
|---|---|---|
| `id` | string | его передают в `answerCallbackQuery` |
| `from` | [User](#user) | кто нажал |
| `message` | [Message](#message) | сообщение с кнопками целиком (вместе с `reply_markup`) |
| `data` | string | `callback_data` нажатой кнопки |
| `date` | number | время нажатия |

#### Chat

Беседа. 🔴 **Проверяйте `type`**: код, рассчитанный на `"dm"`, увидит и другие значения; незнакомые игнорируйте.

| Поле | Тип | |
|---|---|---|
| `id` | string | id беседы — его же передают в `chat_id` |
| `type` | `"dm"` \| `"channel"` \| `"server"` \| `"voice"` | `dm` — беседа 1:1, `channel` — текстовый канал сервера, `server` — сам сервер (только события участия и `getChat`), `voice` — голосовой канал (только методы голоса) |
| `server_id` | string, необязательно | у каналов: сервер |
| `title` | string, необязательно | у каналов и серверов: название |

#### ChatFullInfo

Ответ `getChat`: [Chat](#chat) с подробностями.

| Поле | Тип | |
|---|---|---|
| `id` | string | id беседы |
| `type` | `"dm"` \| `"channel"` \| `"server"` \| `"voice"` | как в [Chat](#chat) |
| `server_id` | string, необязательно | у каналов: сервер |
| `title` | string, необязательно | у каналов и серверов: название |
| `user` | [User](#user), необязательно | в личных: собеседник |
| `member_count` | number, необязательно | у сервера: число участников |

#### ChatMember

Участник сервера (`getChatMember`, `getChatMembers`). Права — не флаги, как в Telegram: роли смотрите через `getServer`.

| Поле | Тип | |
|---|---|---|
| `user` | [User](#user) | участник |
| `status` | `"creator"` \| `"member"` \| `"left"` \| `"kicked"` | `creator` — владелец, `member`, `left`, `kicked` (забанен) |
| `nickname` | string, необязательно | ник на этом сервере (есть, если задан) |
| `role_ids` | массив string | id ролей участника |
| `joined_date` | number, необязательно | когда вступил на сервер |

#### ChatMemberUpdated

Изменилось участие самого бота (`my_chat_member`).

| Поле | Тип | |
|---|---|---|
| `chat` | [Chat](#chat) | беседа |
| `from` | [User](#user) | кто изменил (человек или админ сервера) |
| `date` | number | время события |
| `old_status` | `"creator"` \| `"member"` \| `"left"` \| `"kicked"` | статус до: в личных `member` / `left` / `kicked` |
| `new_status` | `"creator"` \| `"member"` \| `"left"` \| `"kicked"` | статус после |

#### ChatMembersPage

Страница участников сервера.

| Поле | Тип | |
|---|---|---|
| `members` | массив [ChatMember](#chatmember) | участники этой страницы |
| `next_offset` | string, необязательно | передайте его в `offset` за следующей страницей; на последней странице поля нет |

#### Error

Ответ-ошибка; HTTP-статус равен `error_code`. Ветвитесь по `error_code`, а не по тексту `description`.

| Поле | Тип | |
|---|---|---|
| `ok` | `false` | всегда `false` |
| `error_code` | number | HTTP-статус |
| `description` | string | текст для человека, может меняться |
| `retry_after` | number, необязательно | только у `429`: сколько целых секунд подождать (и заголовок `Retry-After`) |

#### InlineKeyboardButton

Кнопка под сообщением: `text` и **ровно одно** из `callback_data` и `url`. Прочие виды кнопок Telegram (`web_app`, `switch_inline_query`, `login_url`, …) отбрасываются.

| Поле | Тип | |
|---|---|---|
| `text` | string | надпись на кнопке (1–64 знаков) |
| `callback_data` | string, необязательно | до **64 байт** UTF-8, а не знаков (кириллица — 2 байта на букву: 32 буквы). Нажатие шлёт боту `callback_query` с этой строкой (≥ 1 знаков) |
| `url` | string, необязательно | только `http(s)`, без `логин:пароль@` в адресе. Для чужих адресов человек видит «Открыть ссылку?» (≤ 2048 знаков) |

#### InlineKeyboardMarkup

Кнопки под сообщением: ряды кнопок, хотя бы один ряд, в ряду 1–8 кнопок, всего не больше 100. Из формы и строки запроса — строкой JSON.

| Поле | Тип | |
|---|---|---|
| `inline_keyboard` | массив массив [InlineKeyboardButton](#inlinekeyboardbutton) | ряды кнопок (≥ 1 элементов; каждый 1–8 элементов) |

#### InputEmbed

Карточка для `sendMessage` (`embeds`), формат как у входящих вебхуков. Картинки карточек — только из хранилища этого инстанса или загруженный файл (`attachment://<имя файла>`, только на серверах); чужая картинка показывается ссылкой.

| Поле | Тип | |
|---|---|---|
| `title` | string или null, необязательно | заголовок (≤ 256 знаков) |
| `description` | string или null, необязательно | текст (≤ 4096 знаков) |
| `url` | string или null, необязательно | ссылка заголовка (≤ 2048 знаков) |
| `color` | integer или null, необязательно | цвет полоски, `0xRRGGBB` числом |
| `timestamp` | string или null, необязательно | время ISO 8601 внизу карточки (≤ 64 знаков) |
| `fields` | массив { name: string, value: string, inline?: any } или null, необязательно | до 25 полей `{ name, value, inline? }` (≤ 25 элементов) |
| `author` | { name: string, url?: string или null, icon_url?: string или null } или null, необязательно | `{ name, url?, icon_url? }` |
| `footer` | { text: string, icon_url?: string или null } или null, необязательно | `{ text, icon_url? }` |
| `image` | { url: string } или null, необязательно | `{ url }` — большая картинка |
| `thumbnail` | { url: string } или null, необязательно | `{ url }` — маленькая картинка |

### Методы

Обязательные параметры выделены. Все методы возвращают `result` внутри `{"ok":true,…}`. Любой метод работает и через `GET` (параметры в строке запроса); из формы и строки запроса числа и флаги можно передавать строками (`limit=50`, `disable_notification=true`), массивы и объекты — строкой JSON.

#### getUpdates

_С API 1._ Забрать новые события (долгий опрос).

| Параметр | Тип | Пределы | |
|---|---|---|---|
| `offset` | integer |  | подтвердить все события с `update_id` **меньше** `offset` (они удаляются) и отдавать начиная с `offset`. Обычно — последний `update_id` + 1. Не задан или ≤ 0 — отдаётся всё неподтверждённое |
| `limit` | integer | 1–100 | по умолчанию 100 |
| `timeout` | integer | 0–50 | секунды, по умолчанию 0 (ответить сразу). Больше 0 — сервер ждёт первое событие до `timeout` секунд (долгий опрос) |
| `allowed_updates` | массив string | ≤ 64 элементов; каждый ≤ 64 знаков | только эти виды событий, например `["message","callback_query"]`. Остальные остаются в журнале до подтверждения `offset`-ом. Незнакомые виды **пропускаются** (не `400`): бот, написанный под сервер новее, продолжает работать |

Результат: массив [Update](#update).

События идут по возрастанию `update_id`. Пока не подтверждено `offset`-ом, одни и те же события приходят снова (так пережидаются перезапуски бота). Если задан адрес доставки — `409`.

**Потребитель один** (как в Telegram): новый `getUpdates` или WebSocket того же бота **сменяет** прежний — ждущий `getUpdates` отвечает `409 Conflict: terminated by other getUpdates request; make sure that only one bot instance is running`, открытый WebSocket закрывается кодом `4009`. Две копии бота с одним токеном выбивают друг друга — оставьте одну. Перевыпуск токена, выключение бота или всех ботов тоже сразу обрывают ждущий `getUpdates` (`401`/`403`), а не отдают ему пачку.

Одновременно два процесса одного бота опрашивать нельзя: они оба увидят одни и те же события и ответят дважды.

```sh
curl -sS "$GV_API/sendMessage" -H "Authorization: Bot $GV_TOKEN" \
  -F chat_id=<chat_id> -F text="Отчёт" -F "files[0]=@report.pdf;type=application/pdf"
```

### События

Журнал событий бота хранится **24 часа**, не больше **1000** событий (у бота «Читать все сообщения» — 10 000; старые уходят первыми, сколько срезано — `dropped_update_count`). Подтверждённые (`offset`, `ack`, ответ `2xx` адреса) удаляются. Каждое событие — [Update](#update): `update_id` и ровно одно из полей ниже.

| Событие | Содержимое | API | Когда |
|---|---|---|---|
| `message` | [Message](#message) | 1 | человек написал боту в личные или в канале пришло сообщение, которое бот вправе видеть (см. [Боты на серверах](#боты-на-серверах-api-3)) |
| `edited_message` | [Message](#message) | 1 | такое сообщение изменили (в каналах фильтр — по новому тексту) |
| `message_deleted` | [MessageDeleted](#messagedeleted) | 1 | сообщение пропало у бота (в личных удалено у обоих; в каналах — ботам «читать всё» и автору) |
| `my_chat_member` | [ChatMemberUpdated](#chatmemberupdated) | 1 | в личных: человек открыл беседу с ботом (`new_status: "member"`; в том числе когда нажал «Написать» заново после удаления чата), удалил её у себя (`"left"`), заблокировал бота (`"kicked"`) или разблокировал; на сервере (`chat.type: "server"`): бота добавили, убрали или забанили |

### WebSocket

Вместо опроса можно держать соединение — события приходят сразу.

```
wss://chat.example.com/api/bot/v1/ws?offset=<N>
Authorization: Bot <токен>
```

Заголовок `Authorization` обязателен, поэтому браузерный `WebSocket` не подходит (он не умеет заголовки) — ботам нужны
серверные клиенты (пакет `ws` в Node, `websockets` в Python). Параметр `offset` необязателен: подтвердить всё до него.

Сообщения — JSON-текст:

| От | Сообщение | |
|---|---|---|
| сервер | `{"op":"hello","bot":<Bot>}` | сразу после подключения |
| сервер | `{"op":"update","update":<Update>}` | события по порядку; сначала накопленные, потом новые |
| клиент | `{"op":"ack","offset":N}` | подтвердить все события с `update_id` меньше `N` (как `offset` у `getUpdates`) |
| клиент | `{"op":"ping"}` → сервер `{"op":"pong"}` | необязательная проверка живости |

Сервер сам шлёт ping-кадры раз в 30 секунд; обычные клиентские библиотеки отвечают автоматически, без ответа соединение
рвётся. События **не подтверждаются сами**: после переподключения неподтверждённые придут снова, поэтому шлите `ack`
(или передавайте `?offset=` при подключении). `allowed_updates` на WebSocket нет — приходят все виды событий.

Коды закрытия:

| Код | Причина |
|---|---|
| 4001 | токен не подходит, перевыпущен, или бот выключен администратором |
| 4003 | боты выключены на инстансе |
| 4009 | задан адрес доставки (`setWebhook`) — WebSocket и адрес не работают вместе; или это соединение сменило другое соединение того же бота (причина `terminated by other connection`: новый WebSocket или `getUpdates` — потребитель один) |
| 4029 | слишком частые подключения |

На 4001, 4003 и 4009 переподключаться по кругу бессмысленно — сначала исправьте причину. На остальные обрывы
переподключайтесь с паузой.

### Доставка на адрес

Третий способ получать события: GusVoice сам шлёт каждое событие `POST`-запросом на адрес вашей программы.
Подходит, если у бота есть публичный `https`-адрес (веб-сервер, функция в облаке).

Доставка — **хотя бы один раз** на любом пути (адрес, `getUpdates`, WebSocket): событие может прийти дважды (приёмник
ответил после срока, адрес сменили во время доставки, бот перезапустился до подтверждения). Отсекайте повторы по
`update_id`; SDK делает это сам.

```sh
curl -sS "$GV_API/setWebhook" -H "Authorization: Bot $GV_TOKEN" \
  -d url=https://bot.example.org/gusvoice -d secret_token=длинная-случайная-строка-16-знаков-и-больше
```

Запрос на ваш адрес:

```
POST /gusvoice HTTP/1.1
Content-Type: application/json
User-Agent: GusVoice-Bot-Webhook/1
X-GusVoice-Signature: t=1761475200,v1=9f2c…(hex)

{"update_id":102,"message":{…}}
```

- Тело — один объект **Update**. События идут **по одному и строго по порядку**: следующее — только после ответа `2xx`
  на предыдущее.
- **Ответ `2xx`** = «принято», событие удаляется. Тело ответа не важно. Любой другой статус, ошибка соединения или молчание
  дольше **10 секунд** = сбой. Редиректы не выполняются (`3xx` — тоже сбой).
- **Повторы:** после сбоя пауза 5 с, затем 10, 20, 40 … но не больше 10 минут между попытками. После **10 сбоев подряд**
  сервер выключает доставку: в `getWebhookInfo` появляется `disabled_date`, события копятся в журнале (24 часа). Включается
  заново новым `setWebhook`. Успешный ответ обнуляет счётчик.
- Ответ читается не больше 4 КБ — отвечайте коротко.

#### Подпись — обязательна, проверяйте её

Заголовок `X-GusVoice-Signature: t=<unix-время>,v1=<hex>`, где

```
v1 = HEX( HMAC-SHA256( ключ = secret_token, данные = t + "." + тело_запроса ) )
```

`тело_запроса` — **сырые байты** как пришли (не перекодированный JSON). Что проверить:

1. пересчитать HMAC и сравнить со `v1` функцией постоянного времени;
2. `|сейчас − t| ≤ 300` секунд — иначе запрос могли перехватить и повторить позже.

**Почему подпись обязательна.** Адрес бота — обычный публичный URL, и его может узнать кто угодно. Без подписи любой
отправит туда выдуманное событие «команда `/restart` от владельца» — и бот выполнит её. Подпись доказывает, что запрос
сделал GusVoice, а не посторонний; секрет известен только вам и серверу. Поэтому `secret_token` у нас обязателен (в
Telegram он необязателен только из-за старых ботов).

Готовые проверки — в [примерах](#python-requests-без-sdk) ниже.

#### Защита от SSRF

Доставка — это исходящий запрос **нашего** сервера по адресу, который задали вы. Чтобы им нельзя было ходить во
внутреннюю сеть инстанса, сервер:

- принимает только `https://` (`http://` — лишь если администратор включил «внутренние адреса»);
- не принимает адрес с логином и паролем;
- проверяет **каждый** IP, в который разворачивается имя, и соединяется строго с проверенным;
- по умолчанию запрещает частные сети, loopback, link-local, CGNAT, служебные диапазоны и адрес метаданных облака
  `169.254.169.254`. «Внутренние адреса» открывают **только локальную сеть** (`10/8`, `172.16/12`, `192.168/16`,
  `fc00::/7`…); loopback (`127.0.0.0/8`, `::1`, `::ffff:127.x` — сам сервер), `0.0.0.0/8`, `169.254.0.0/16`, multicast и
  зарезервированные диапазоны запрещены всегда;
- не следует за редиректами, ограничивает время ответа (10 с) и его размер (4 КБ).

Если бот живёт в той же локальной сети, что и сервер, попросите администратора включить «Разрешить доставку на
внутренние адреса» — либо пользуйтесь опросом/WebSocket, им это не нужно. Бот на самой машине сервера (`localhost`)
доставку на адрес не получит вовсе: только опрос или WebSocket.

### «Прочитано»

У человека под сообщением, отправленным боту, появляется ✓✓ **в момент, когда бот забрал событие**: `getUpdates`
вернул его, или пришёл `ack` / `?offset=` по WebSocket, или ваш адрес ответил `2xx`. Не когда бот ответил — как в Telegram.
Правки, удаления и `my_chat_member` прочтение не двигают. Отправка сообщения ботом тоже отмечает беседу прочитанной до
этого момента.

### Приватность

- **Новый бот — приватный.** Открыть с ним беседу и писать ему может только владелец. Чтобы пользоваться ботом
  могли другие, в «Мои боты» включите **«Доступен всем»**. Публичного бота можно найти в поиске людей; приватного —
  только владелец.
- Проверка идёт на **каждой отправке**, а не только при открытии беседы: стал бот снова приватным или его выключили —
  у тех, с кем беседа уже есть, отправка отвечает `403` (текст, файлы, голосовые, пересылка в беседу, отложенные,
  нажатия кнопок), а приложение показывает плашку вместо поля ввода. Событий от них бот не получает.
- Бот видит только то, что написано **ему в личные**. Больше ничего: ни серверов, ни каналов, ни других бесед.
- Бот **не пишет первым** (антиспам, как в Telegram): у него нет способа создать беседу, только отвечать в уже открытой.
- Боты не добавляются в группы и не ходят в федерацию (этап 1).
- Администратор инстанса видит всех ботов и может выключить любого одним нажатием. Удалили аккаунт владельца — удаляются
  и его боты; сообщения, уже написанные ботом, остаются в беседах.

### Безопасность автора бота

- **Проверяйте `from.id`.** Бот управления сервером без проверки выполнит `/restart` для **любого**, кто смог ему
  написать. Держите свой id (его показывает `getUpdates` в событии от вас) в переменной окружения или списке и
  игнорируйте всех остальных. Ник менять можно, id — нет, проверяйте именно id.
- **Держите бота приватным**, пока он не должен быть публичным: «Доступен всем» — только если проверка по `from.id` есть.
- **Токен — пароль.** В переменной окружения или секрет-хранилище, не в коде, не в репозитории, не в чатах и скриншотах.
  Префикс `gvb_` нужен, чтобы сканеры секретов (в том числе GitHub) узнавали утечку. Утёк — «Перевыпустить токен» в
  «Мои боты»: старый перестаёт работать сразу, открытые WebSocket закрываются.
- **Проверяйте подпись** доставки на адрес и окно времени (см. выше).
- Не выполняйте текст из сообщений как команду оболочки и не подставляйте в неё без белого списка:
  `/restart ; rm -rf /` должен упираться в список разрешённых имён.
- **Кнопки — не тайный канал.** `callback_data` видит клиент человека, и приходит оно от него. Сервер гарантирует только
  совпадение с кнопкой текущего сообщения; всё равно проверяйте `from.id` при каждом нажатии и перепроверяйте значения
  из `data` (имена служб, id) по белому списку. Токены и секреты в `callback_data` не кладите.

### Кнопки и команды (этап 2)

**Кнопки.** Передайте `reply_markup` в `sendMessage` (или `editMessageText` / `editMessageReplyMarkup`). Нажатие приходит
боту событием `callback_query`; ответьте `answerCallbackQuery` (хотя бы без текста — так гаснут «часики» на кнопке).
Обычная панель правит своё же сообщение на месте:

```sh
curl -sS "$GV_API/sendMessage" -H "Authorization: Bot $GV_TOKEN" -H 'content-type: application/json' -d '{
  "chat_id": "<chat_id>", "text": "Панель сервера",
  "reply_markup": {"inline_keyboard": [[{"text":"Статус","callback_data":"st"},{"text":"Перезапустить…","callback_data":"rs"}]]}}'
# приходит нажатие:  {"update_id":…,"callback_query":{"id":"cbq_…","from":{…},"message":{…},"data":"rs","date":…}}
curl -sS "$GV_API/answerCallbackQuery" -H "Authorization: Bot $GV_TOKEN" -d callback_query_id=cbq_… -d text="Перезапускаю…"
```

Правила, которых можно не ожидать:

- 🔴 **`editMessageText` без `reply_markup` снимает кнопки** — ровно как в Telegram. Чтобы оставить, передайте их снова.
- Нажатие принимается только для кнопки, которая **сейчас** под сообщением: сервер сверяет `data` с текущими кнопками.
  Старые кнопки (вы сменили клавиатуру) и выдуманный `data` отсекаются до вас.
- `callback_query` старше **25 секунд** **не отдаётся** (ни `getUpdates`, ни WebSocket, ни доставкой на адрес): бот,
  лежавший час, при старте не выполнит старое нажатие «Перезапустить».
- Старые клиенты GusVoice кнопок не показывают — текст сообщения остаётся читаемым. Держите главное доступным и
  командами (`/status`, `/restart nginx`).

**Команды.** `setMyCommands` публикует список для подсказки по `/`. Отдельного события у команд нет: выбор человека
вставляет `/status ` в поле, он отправляет — вам приходит обычный `message`.

### Python (requests, без SDK)

Бот с долгим опросом, отвечает только владельцу, переживает `429` и сетевые сбои:

```python
import os
import time

import requests

API = os.environ["GV_API"] + "/api/bot/v1"          # например https://chat.example.com/api/bot/v1
TOKEN = os.environ["GV_BOT_TOKEN"]
OWNER_ID = os.environ["GV_OWNER_ID"]                 # ваш id: команды принимаются только от вас
S = requests.Session()
S.headers["Authorization"] = f"Bot {TOKEN}"


def call(method, **params):
    while True:
        r = S.post(f"{API}/{method}", json=params, timeout=70)
        data = r.json()
        if data.get("ok"):
            return data["result"]
        if data["error_code"] == 429:                # предел частоты: ждём и повторяем
            time.sleep(data.get("retry_after", 1))
            continue
        raise RuntimeError(f'{data["error_code"]} {data["description"]}')


def handle(msg):
    if msg["from"]["id"] != OWNER_ID:                # эту проверку не убирайте
        return
    text = msg.get("text", "")
    if text == "/start":
        call("sendMessage", chat_id=msg["chat"]["id"], text="Готов. Попробуйте /ping")
    elif text == "/ping":
        call("sendMessage", chat_id=msg["chat"]["id"], text="pong")


offset = 0
while True:
    try:
        updates = call("getUpdates", offset=offset, timeout=30)
    except (requests.RequestException, RuntimeError) as e:
        print("опрос не удался:", e)
        time.sleep(5)
        continue
    for u in updates:
        offset = u["update_id"] + 1                  # подтверждает всё, что раньше
        if "message" in u:
            handle(u["message"])
```

Приём доставки на адрес с проверкой подписи (стандартная библиотека):

```python
import hashlib
import hmac
import time
from http.server import BaseHTTPRequestHandler, HTTPServer

SECRET = "тот-же-secret_token-что-в-setWebhook"


def verify(secret: str, header: str, body: bytes, tolerance: int = 300) -> bool:
    try:
        parts = dict(p.split("=", 1) for p in header.split(","))
        t, sig = int(parts["t"]), parts["v1"]
    except (KeyError, ValueError):
        return False
    if abs(time.time() - t) > tolerance:             # защита от повтора
        return False
    mac = hmac.new(secret.encode(), f"{t}.".encode() + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(mac, sig)


class Hook(BaseHTTPRequestHandler):
    def do_POST(self):
        body = self.rfile.read(int(self.headers.get("Content-Length", 0)))
        if not verify(SECRET, self.headers.get("X-GusVoice-Signature", ""), body):
            self.send_response(401)
            self.end_headers()
            return
        print("событие:", body.decode())
        self.send_response(200)                      # 2xx = принято; иное = придёт повтор
        self.end_headers()


HTTPServer(("0.0.0.0", 8080), Hook).serve_forever()   # за https-прокси (nginx, Caddy)
```

```js
// Долгий опрос. Node 18+, встроенный fetch.
const API = `${process.env.GV_API}/api/bot/v1`;
const TOKEN = process.env.GV_BOT_TOKEN;
const OWNER_ID = process.env.GV_OWNER_ID; // ваш id: команды принимаются только от вас

async function call(method, params = {}) {
  for (;;) {
    const res = await fetch(`${API}/${method}`, {
      method: 'POST',
      headers: { Authorization: `Bot ${TOKEN}`, 'Content-Type': 'application/json' },
      body: JSON.stringify(params),
    });
    const data = await res.json();
    if (data.ok) return data.result;
    if (data.error_code === 429) { // предел частоты: ждём и повторяем
      await new Promise((r) => setTimeout(r, (data.retry_after ?? 1) * 1000));
      continue;
    }
    throw new Error(`${data.error_code} ${data.description}`);
  }
}

let offset = 0;
for (;;) {
  let updates;
  try {
    updates = await call('getUpdates', { offset, timeout: 30 });
  } catch (e) {
    console.error('опрос не удался:', e.message);
    await new Promise((r) => setTimeout(r, 5000));
    continue;
  }
  for (const u of updates) {
    offset = u.update_id + 1; // подтверждает всё, что раньше
    const m = u.message;
    if (!m || m.from.id !== OWNER_ID) continue; // эту проверку не убирайте
    if (m.text === '/start') await call('sendMessage', { chat_id: m.chat.id, text: 'Готов. Попробуйте /ping' });
    else if (m.text === '/ping') await call('sendMessage', { chat_id: m.chat.id, text: 'pong' });
  }
}
```

Проверка подписи доставки на адрес:

```js
import { createServer } from 'node:http';
import { createHmac, timingSafeEqual } from 'node:crypto';

const SECRET = process.env.GV_HOOK_SECRET; // тот же secret_token, что в setWebhook

function verify(secret, header, rawBody, tolerance = 300) {
  const p = Object.fromEntries((header ?? '').split(',').map((kv) => kv.split('=')));
  const t = Number(p.t);
  if (!Number.isInteger(t) || !p.v1 || Math.abs(Date.now() / 1000 - t) > tolerance) return false;
  const mac = createHmac('sha256', secret).update(`${t}.`).update(rawBody).digest();
  const got = Buffer.from(p.v1, 'hex');
  return got.length === mac.length && timingSafeEqual(got, mac);
}

createServer(async (req, res) => {
  const chunks = [];
  for await (const c of req) chunks.push(c);
  const raw = Buffer.concat(chunks); // подпись считается по сырым байтам, не по перекодированному JSON
  if (!verify(SECRET, req.headers['x-gusvoice-signature'], raw)) {
    res.writeHead(401).end();
    return;
  }
  console.log('событие:', JSON.parse(raw.toString('utf8')));
  res.writeHead(200).end(); // 2xx = принято; иное = придёт повтор
}).listen(8080);
```

## Боты на серверах (API 3)

С `api_version` 3 (`getMe.features` содержит `servers`) бот может стоять на серверах: писать в текстовые каналы, ставить кнопки, отвечать на команды, модерировать.

**Как бот попадает на сервер.** Админ с правом «Управлять сервером» открывает «Настройки сервера → Интеграции → Боты → Добавить бота» и вводит ник. Публичного бота («Доступен всем») может добавить любой такой админ, приватного — только его владелец. На сервере создаётся **роль бота** с именем бота: права в ней — не больше, чем у добавившего, и **никогда** не «Администратор». Роль нельзя удалить или выдать другому; права правятся в «Ролях» как у обычной роли. Ботов на сервере — не больше 20. Убрать бота: там же «Убрать с сервера», кик или бан бота, `leaveChat` от имени бота, или владелец бота в «Мои боты → Серверы → Убрать». Роль уходит вместе с ботом, а события этого сервера в журнале бота удаляются.

**Чаты.** `chat.type`: `dm` — беседа 1:1, `channel` — текстовый канал (`server_id`, `title`), `server` — сам сервер (только в событиях членства и `getChat`). 🔴 **Проверяйте `chat.type`**: старый код, сверявший `type === 'dm'`, увидит новые значения. Методы сообщений принимают `chat_id` беседы или канала; id сервера → `400 chat is a server; use a channel id`, голосовой канал → `400 chat is not a text channel`, чужое или невидимое → `400 chat not found`.

**Приватность.** По умолчанию бот получает из канала только:
1. команды — текст начинается с `/`: `/cmd@ваш_ник` — только вам, `/cmd@другой` — не вам, `/cmd` без ника — всем ботам канала;
2. личное упоминание `@ваш_ник` (`@everyone`/`@here` не в счёт);
3. упоминание роли бота;
4. ответы на ваши сообщения.

Галочка «Читать все сообщения» (ставит админ) снимает фильтр. Фильтр считается на сервере ДО записи в журнал: чего бот видеть не должен, у него не хранится вовсе. Правка (`edited_message`) проверяется по НОВОМУ тексту. Сообщения **других ботов** не приходят никогда (защита от петель); сообщения вебхуков — только ботам «читать всё». Бот видит только каналы, где у его роли есть «Видеть канал».

**События** (`allowed_updates` их понимает): `message`, `edited_message`, `message_deleted` (ботам «читать всё» и автору удалённого), `callback_query` (кнопки под сообщением бота в канале; `message.chat.type === 'channel'`), `message_reaction` (наборы реакций человека до и после — `old_reaction`/`new_reaction`; ботам «читать всё» и автору сообщения; в ЛС — на любое сообщение беседы с ботом), `chat_member` (кто-то вошёл, вышел, кикнут, забанен, разбанен — всем ботам сервера; `from` — кто сделал, `user` — с кем), `my_chat_member` (самого бота добавили, убрали, забанили — `chat.type === 'server'`). Статусы: `creator`, `member`, `left`, `kicked` (забанен). Закрепы, опросы и стикеры событиями не приходят. Порядок событий между процессами сервера не гарантирован: `edited_message` может прийти по сообщению, которого бот не видел.

**Гости с других инстансов.** У человека с другого сервера в `from`/`user` есть `instance_domain`; ник может совпасть с ником местного. Проверяйте права по `from.id`, а не по нику.

**Методы.** Прежние (`sendMessage`, `editMessageText`, `editMessageReplyMarkup`, `deleteMessage`, `sendChatAction`, `getChat`) работают и в канале; файлы в канале — публичные (как у вебхуков); `client_id` в каналах пока не учитывается. Новые:

| Метод | Параметры | Право бота |
|---|---|---|
| `setMessageReaction` | `chat_id`, `message_id`, `reaction: [{type:'emoji', emoji}]` (0–3, набор заменяется; пусто — снять) | видеть канал; работает и в ЛС |
| `pinChatMessage` / `unpinChatMessage` | `chat_id`, `message_id` | «Управлять сообщениями» |
| `getChatMember` | `chat_id` (сервер или канал), `user_id` | участник |
| `getChatMemberCount` | `chat_id` (сервер) | участник |
| `getChatMembers` | `chat_id`, `offset?`, `limit?` (≤ 200) → `{members, next_offset?}` | участник |
| `getMyServers` | — → `[{id, title}]` | — |
| `getServer` | `server_id` → каналы (видимые боту, `can_send`) и роли (`managed`) | участник |
| `getChatHistory` | `chat_id` (канал), `before_message_id?`, `limit?` (≤ 100) | только «читать всё» + «Читать историю» |
| `addChatMemberRole` / `removeChatMemberRole` | `chat_id`, `user_id`, `role_id` | «Управлять ролями», роль ниже роли бота |
| `banChatMember` / `unbanChatMember` | `chat_id`, `user_id`, `reason?` | «Банить участников», цель ниже бота |
| `kickChatMember` | `chat_id`, `user_id` | «Выгонять участников», цель ниже бота |
| `leaveChat` | `chat_id` (сервер) | — |

`ChatMember` = `{user, status, nickname?, role_ids, joined_date?}`. Права — битовые: роли участника (`role_ids`) + `getServer().roles`.

**Команды.** `setMyCommands` принимает `scope: {type: 'all_group_chats'}` — список для серверов. На сервере берётся `all_group_chats`, если задан, иначе `default`; в ЛС — `all_private_chats`, иначе `default`.

**Формат текста.** Без `parse_mode` — наша разметка (`**жирный**`, `__курсив__`, `~~зачёркнутый~~`, `||скрытый||`, `` `код` ``, `> цитата`). `parse_mode: 'HTML'` — подмножество Telegram (`b`, `i`, `u`, `s`, `code`, `pre`, `tg-spoiler`, `a href`, `blockquote`) переводится в нашу разметку; неизвестные теги снимаются. `MarkdownV2` → 400.

**Пределы.** В один канал — 5 сообщений за 5 с, на сервер — 30 в минуту (реакции и закрепы — туда же); `getChatHistory`/`getChatMembers` — 10 за 10 с. Журнал бота «читать всё» — до 10 000 событий (иначе 1000); сколько срезано — `dropped_update_count` в `getMe` и `getWebhookInfo`.

**Пакетная доставка на адрес.** `setWebhook(…, batch: true)` — тело POST становится массивом до 100 событий, подпись — по всему телу; 2xx подтверждает всю пачку, иначе пачка повторяется целиком. SDK (`webhookHandler`) понимает и объект, и массив.

## Голос (API 4)

С `api_version` 4 (`getMe.features` содержит `voice`) бот может **играть звук в голосовом канале** (музыка, озвучка,
таймеры). Людей бот **не слышит никогда**: сервер выдаёт ему токен LiveKit с `canSubscribe: false`, и ни одна дорожка
человека до бота не доходит — даже с изменённым SDK. Бот публикует только одну дорожку-микрофон: без камеры, экрана,
сообщений данных и атрибутов.

**Включение.** Тумблер админа инстанса «Боты могут заходить в голосовые каналы» (`PUT /admin/bots/settings` `{voice}`; нет
поля — можно, общий выключатель ботов и так по умолчанию выключен). Выключение выкидывает всех ботов из всех комнат. На
сервере у роли бота в этом канале нужны «Просмотр канала», **«Подключаться»** и **«Говорить»**.

**Методы.**
- `joinVoice(chat_id, bitrate?)` — `bitrate` 24000–128000, по умолчанию 64000 (возвращается в `audio`). Ответ
  `{url, token, room, chat, server_muted, expires_in, audio: {sample_rate: 48000, channels: 2, bitrate}}`: подключиться к
  LiveKit по `url` с `token` (живёт 10 минут; пока сессия жива, LiveKit продлевает его сам, после полного обрыва — снова
  `joinVoice`) и публиковать PCM 48 кГц стерео дорожкой `MICROPHONE`. `chat.type === 'voice'`. На сервере — один голосовой
  канал: вход в другой канал того же сервера переносит бота (старая комната закрывается). Ошибки по порядку:
  `403 voice is disabled for bots on this server`, `400 chat not found`, `400 chat is a server; use a channel id`,
  `400 chat is not a voice channel`, `403 not enough rights to connect to the voice chat`,
  `403 not enough rights to speak in the voice chat`, `429` (6 входов в минуту), `400 too many bots in the voice chat`
  (3 бота на канал), `400 too many active voice chats` (10 каналов на бота).
- `leaveVoice(chat_id?)` — выйти из этого канала, без `chat_id` — из всех. Идемпотентно: всегда `true`.
- `getVoiceChatMembers(chat_id)` — кто сейчас в канале: `[{user, muted, deafened, server_muted, is_bot}]` (тот же источник,
  что видит приложение). 30 в минуту на сервер.

**Событие `voice_state`** — `{chat, user, action: 'joined'|'left', date, move_to?}` приходит всем живым ботам сервера, которые
видят канал, в том числе о входах и выходах самого бота (так он узнаёт, что его отключили). `move_to` — только самому боту,
когда его перенёс модератор: SDK сам заходит в `move_to`. Человек со слабой сетью может дать `left` → `joined` за пару секунд.

**Модерация.** Модератор глушит бота для всех (право на микрофон отзывается, размьют возвращает), отключает и переносит его
обычным меню голоса; перенос проверяет права бота в целевом канале (`403 the bot can't connect to that channel`). Тычок и
награды магазина боту недоступны (`400 bots don't accept this`). У каждого слушателя своя громкость бота и «Заглушить для
себя».

**Сервер выкидывает бота** из голоса, когда бота выключили, перевыпустили токен, удалили, сняли/кикнули/забанили на сервере,
выключили голос ботов, отняли «Подключаться»/«Говорить» (в течение минуты) или **бот 5 минут сидит в канале один (без
людей)**. Выкинутый получает `voice_state left`; после такого выхода SDK не переподключается. Режим «радио» — вернуться по
`voice_state joined` человека.

**Боты других инстансов** в наши голосовые каналы не заходят (Bot API живёт только на домашнем инстансе бота); гости с
других инстансов в нашем канале слышат нашего бота, как любого участника. Авторские права на то, что играет бот, — на
владельце бота и сервера.

## Отличия от Telegram

Идея та же (`getUpdates`/`setWebhook`, `{ok, result}`, `offset`), поэтому знакомый с Telegram переучивается быстро.

| Telegram | GusVoice |
|---|---|
| Токен в адресе `/bot<токен>/метод` | Токен в заголовке `Authorization: Bot <токен>`, адрес `/api/bot/v1/метод` |
| Токен выдаёт BotFather командами | Токен выдаёт «Мои боты» кнопками |
| `chat_id`, `message_id`, `user.id` — числа | Строки (UUID) |
| `chat.type` — `private`, `group`, … | `dm`, `channel`, `server`, `voice` |
| `update_id` идут подряд | Растут, но с пропусками (счётчик общий на инстанс): подтверждайте `last + 1`, не ждите `+1` |
| `secret_token` у вебхука необязателен, приходит в заголовке | **Обязателен** (≥ 16 знаков), по нему считается HMAC-подпись `X-GusVoice-Signature` |
| Вебхук — `https`, порты 443/80/88/8443 | `https`, любой порт; `http` и внутренние адреса — только если админ разрешил |
| `parse_mode` (Markdown/HTML) | Без него — разметка GusVoice; `HTML` — подмножество Telegram; `MarkdownV2` → `400` |
| `sendPhoto`, `sendDocument`, … | Одно `sendMessage` с `files[0]…files[9]` (multipart) |
| `getFile` | Ссылка прямо в `attachments[].url` |
| `reply_to_message_id` | То же имя поля |
| `allowed_updates` | Только у `getUpdates` (на WebSocket приходят все виды) |
| `my_chat_member` | Есть: `member`/`left`/`kicked` у личной беседы |
| — | Есть `message_deleted` |
| Меню команд (`setMyCommands`) | Есть; `scope` — только `default`/`all_private_chats`/`all_group_chats`, без `language_code`. Команда приходит обычным сообщением `/status` |
| Кнопки под сообщением (`inline_keyboard`), `callback_query` | Есть: только кнопки `callback_data` и `url`; в `callback_query` нет `chat_instance`/`inline_message_id` |
| `editMessageText` без `reply_markup` снимает кнопки | Так же |
| `editMessageReplyMarkup` без изменений → `400 message is not modified` | Отдаёт сообщение, без ошибки |
| `answerCallbackQuery` с `url`, `cache_time` | Пока нет: только `text` и `show_alert` |
| Неотвеченное нажатие — клиент ждёт сервер | 15 секунд, потом человек видит «бот не ответил»; нажатия старше 25 с боту не отдаются |
| Любое `callback_data` от изменённого клиента доходит до бота | Только `callback_data` кнопки, которая сейчас под сообщением; остальное отсекает сервер |
| Боты в группах, каналах | Есть на серверах (каналы); групповых бесед для ботов нет |
| Режим приватности в группах | Как в Telegram: команды, упоминания и ответы боту; всё — только с «Читать все сообщения» |
| Голосовые чаты | Есть: бот играет звук (`joinVoice`, `@gusvoice/bot-voice`), людей не слышит |
| Боты общаются со всеми, кто нажал Start | Новый бот приватный; «Доступен всем» включает владелец |
| Бот может написать, если человек его когда-то запускал | Бот пишет только в уже открытую беседу и не может её создать |

## FAQ

**Бот не отвечает на `getMe`, `401`.** Токен введён неверно, перевыпущен, бот выключен администратором, либо заголовок
не в виде `Authorization: Bot <токен>` (слово `Bot`, а не `Bearer`).

**`403 bots are disabled on this instance`.** Администратор выключил боты на инстансе («Админ-панель → Боты»).

**`400 chat not found` при `sendMessage`.** Беседа с ботом не открыта человеком или `chat_id` не от этого бота. Откройте
беседу в приложении и берите `chat.id` из события.

**`getUpdates` возвращает `409`.** Задан адрес доставки — `deleteWebhook`, если нужен опрос. Или `terminated by other
getUpdates request`: запустилась другая копия бота с тем же токеном (опрос или WebSocket) — оставьте одну.

**События приходят снова и снова.** Вы не подтверждаете их: передавайте `offset = последний update_id + 1`.

**Бот отвечает дважды.** Доставка «хотя бы один раз» — отсекайте повторы по `update_id`. Два экземпляра с одним токеном
события больше не делят: новый сменяет старый (`409`/`4009`).

**Сообщение пришло, а события нет.** Бот выключен/боты выключены; бот приватный, а пишет не владелец (беседу
создать не удастся); адрес доставки задан и сломан (смотрите `getWebhookInfo`); события старше 24 часов уходят из журнала.

**Доставка на адрес остановилась.** `getWebhookInfo` покажет `disabled_date` и `last_error_message`. Почините
приёмник и снова вызовите `setWebhook`.

**`setWebhook` отвечает `bad webhook: адрес внутренний`.** Имя разворачивается во внутренний IP, а админ не разрешил
внутренние адреса. Используйте публичный адрес, опрос или WebSocket, либо попросите включить «Разрешить доставку на
внутренние адреса».

**Как узнать свой `id`?** Напишите боту любое сообщение и посмотрите `from.id` в событии `message`.

**Токен утёк.** «Мои боты» → ваш бот → «Перевыпустить токен». Старый перестаёт работать сразу.

**Можно ли удалить бота?** Да: «Мои боты» → «Удалить бота». Токен гаснет, события и адрес снимаются, сообщения бота
остаются в беседах.

**Что значит «v1»?** Документация описывает Bot API v1. Он меняется только добавлениями: новые поля, методы и
виды событий появляются, старые не ломаются. Неизвестные поля и события нужно спокойно пропускать, тогда бот переживёт
обновление инстанса. Ломающие изменения, если понадобятся, выйдут как `v2` рядом с `v1`.
