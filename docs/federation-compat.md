# Контракт совместимости версий (федерация и чужие бэкенды)

> 🔴 **Обязательно к соблюдению** для любой правки бэкенда, протокола и клиента.
> Требование (2026-09-14): *изменения на основном инстансе, по сути dev-сервере, не должны в будущем ломать федерацию;
> бэкенд должен быть иммунным к несоответствиям версий.*

---

## Почему это не абстракция

- **Основной инстанс проекта — dev-стенд.** Каждый push в `master` сразу уезжает на него.
- **Соседи будут на публичных релизах**, а публичные релизы выходят реже, чем меняется `master` (отставание — десятки версий).
- **Десктоп вшивает фронт** и обновляется только тегом. Клиент человека может быть и старше, и новее бэкенда,
  к которому он подключается. С федерацией клиент ходит **напрямую в чужие бэкенды** других версий.

⇒ В любой момент живут одновременно: `master` ↔ последний публичный релиз ↔ десктопы нескольких версий.
Ломается любое место, которое молча предполагает «обе стороны — одна версия».

## Правила

### 1. Версия протокола отдельна от версии приложения

- Протокол федерации — `gv-fed/<major>`. Документ инстанса отдаёт `protocol: {min, max}`, `features: [...]` и
  `app_version` (последнее — только для диагностики, **решения по нему не принимаются**).
- Возможности соседа определяются **только по `features`**. Новое поведение, которого сосед может не знать,
  включается, только если он объявил нужную возможность. Иначе — старое поведение или понятный отказ.

### 2. Внутри мажорной версии — только добавления

- Можно: новое **необязательное** поле с безопасным значением по умолчанию, новый тип события, новый маршрут, новое
  значение `features`.
- Нельзя: удалить или переименовать поле, сменить тип или смысл поля, сделать необязательное обязательным, сузить
  допустимые значения, изменить формат идентификаторов, подписи или времени.
- **Коды отказов — тоже протокол.** Клиент по ним показывает человеку причину (`federation.server_closed` → окно
  «сервер закрыт держателем», «код только для своих» и т.п.). Код никогда не переименовывается и не меняет смысл;
  новая причина = новый код, а клиент, который его не знает, показывает общий текст ошибки с исходным сообщением.
  Коды, заложенные планом v5 (реестр пополняется только добавлением): `federation.server_closed`,
  `federation.dm_unavailable`, `federation.owner_must_be_local`, `federation.quota_exceeded`, `federation.paused`,
  `federation.clock_skew`, `federation.trust_lost`, `federation.banned`.
- Ломающее изменение = **новый мажор**: `/api/fed/v2/...` **рядом** с v1. v1 живёт окно поддержки —
  **не меньше двух публичных релизов и не меньше 6 месяцев** после выхода v2 — и снимается отдельным решением.

### 3. Терпимый читатель — в обе стороны

- Неизвестные поля **игнорируются**. Zod-схемы протокола не используют `.strict()` (на 14.09 в коде `.strict()` нет
  нигде — так и держать для всего, что принимается от чужих).
- Неизвестные типы событий **пропускаются молча** (клиентский `switch` в `sockets.ts` сейчас без `default` — это
  правильно, не добавлять туда броска ошибки).
- Неизвестное значение перечисления → безопасная деградация (не показать, показать «обновите X»), а не падение.

### 4. Провод отделён от БД

- Всё, что уходит соседу или чужому клиенту, строится **явными сериализаторами протокола**, а не выгрузкой строк БД.
  Миграции на проде не имеют права менять провод.
- Идентификаторы в проводе — `(instance_id, user_id)`; логин и почта никогда не ключ (#140).

### 5. Недоступный или несовместимый сосед — не авария

- Нет связи → «инстанс недоступен», локальные серверы работают.
- Нет общей версии протокола → «на стороне X нужна новая версия», без попыток и без падений.
- Ошибки соседа изолированы: одна связка не блокирует очередь, запросы и отрисовку остальных.

### 6. Клиент ↔ чужой бэкенд

- API бэкенда для клиентов — те же правила 2–3 (добавления, терпимый читатель в обе стороны).
- Клиент читает `features` инстанса, к которому подключается, и **прячет** то, чего тот не умеет, вместо того чтобы
  звать несуществующий маршрут.

## Как это проверяется (а не держится на памяти)

| Механизм | Что ловит | Когда появляется |
|---|---|---|
| **Фикстуры протокола** `packages/shared/src/federation/fixtures/v<major>/*.json` — примеры каждого сообщения каждой версии | удаление или переименование поля: все исторические фикстуры обязаны разбираться текущими схемами | F1 |
| **Страж append-only** (скрипт в духе `scripts/check-tests-listed.mjs`, шаг в джобе `checks`) | правку или удаление уже существующей фикстуры — это и есть ломающее изменение под видом «поправил пример» | F1 |
| **Тест «новый отправитель → старая схема»** | новое сообщение, которое не разберёт сосед на минимальной поддерживаемой версии | F1 |
| **Интероп-джоба в CI: `master` ↔ последний публичный релиз** (два бэкенда в compose) | реальную несовместимость по сценарию: связка → каталог → приглашение → гостевая сессия → сообщение → токен голоса | F5 |

**Любой PR, трогающий `packages/shared/src/federation/**`, `/api/fed/**` или DTO/WS-события, которые видят
чужие клиенты, отвечает на вопрос: «это только добавление? что увидит сосед на прошлом публичном релизе?»**
