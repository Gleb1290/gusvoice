# Свой бот с помощью нейронки: пошаговый плейбук

> Справочник для людей: [bots.ru.md](bots.ru.md) · файл для вставки в нейронку: [bots-llm.md](bots-llm.md) ·
> English: [bots-playbook.md](bots-playbook.md)

Для кого: вы не программист (или давно не писали код), но хотите бота — например, чтобы управлять своим VPS из
GusVoice или получать уведомления. План простой: **создаёте бота в приложении → даёте нейронке документацию и просьбу →
запускаете то, что она написала → проверяете**. Ниже — каждый шаг и что делать, если не получилось.

Что понадобится: аккаунт GusVoice на инстансе, где администратор **включил боты** (см.
[«Как включить»](bots.ru.md#как-включить-администратор-инстанса)); любая нейронка, которая пишет код; машина, где бот
будет работать круглосуточно (VPS, домашний сервер, Raspberry Pi). Для быстрой пробы сгодится и ваш компьютер.

---

## Шаг 1. Создайте бота и получите токен

1. Настройки → **«Мои боты»** → «Создать бота».
2. Ник — латиницей и **с окончанием `bot`**: `vps_panel_bot`. Имя — любое, например «Сторож VPS».
3. **Скопируйте токен сразу** (начинается с `gvb_`). Он показывается один раз. Положите в менеджер паролей. Потеряли —
   «Перевыпустить токен» (старый перестанет работать).
4. Нажмите «Открыть беседу» → «Старт». Бот пока молчит — это нормально, программы ещё нет.

Бот **приватный**: писать ему можете только вы. Не включайте «Доступен всем», пока бот не проверяет, кто ему пишет.

## Шаг 2. Узнайте свой id и адрес API

- **Адрес API** — адрес вашего инстанса, например `https://chat.example.com` (тот же, что в адресах вебхуков). Уточните у
  администратора, если не знаете.
- **Ваш id** — нужен боту, чтобы слушаться только вас. Получить так (в терминале на любой машине с `curl`):

```sh
export GV_API=https://chat.example.com
export GV_BOT_TOKEN=gvb_...вставьте_токен...
curl -sS "$GV_API/api/bot/v1/getUpdates?timeout=5" -H "Authorization: Bot $GV_BOT_TOKEN"
```

В ответе найдите `"from":{"id":"…"` — это **ваш id** (длинная строка с дефисами), а рядом `"chat":{"id":"…"` — id вашей
беседы с ботом (понадобится для скриптов-уведомлялок). Если ответ пустой `"result":[]` — напишите боту `/start` и
повторите.

> Эта команда ничего не удаляет: события останутся в журнале, пока программа бота не подтвердит их (`offset`). Зато ваши
> сообщения боту получат ✓✓ — «бот забрал».

## Шаг 3. Дайте задание нейронке

1. Откройте чат с нейронкой (ChatGPT, Claude, Gemini, локальная модель — любая).
2. **Вставьте целиком файл [`bots-llm.md`](bots-llm.md)** (кнопка «Raw» в репозитории → выделить всё → копировать).
   В конце файла три готовых запроса.
3. Сразу за ним вставьте **свой запрос** — возьмите готовый из раздела 11 файла и отредактируйте выделенное
   (белый список служб, пороги, часовой пояс):

| Хочу | Шаблон |
|---|---|
| Управлять VPS: `/status`, `/restart nginx`, только я | «Шаблон 1 — бот-панель VPS» |
| Получать уведомления из cron / скриптов | «Шаблон 2 — бот-уведомлялка» |
| Напоминания в личку | «Шаблон 3 — бот-напоминалка» |

В «Шаблоне 1» уже есть панель **кнопками** (`/panel`: «Статус», «Перезапустить… → служба → Да/Нет») и меню команд по `/`.
Готовый пример на SDK — [`examples/bots/vps-panel.ts`](../examples/bots/vps-panel.ts).

4. Ответьте на вопросы нейронки (где запускаете, какой язык). Если спрашивает про токен — **ничего не вставляйте**,
   токен только в файл окружения на вашей машине (шаг 4).

Хороший признак: код читает токен и адрес из переменных окружения, проверяет `from.id`, не использует `shell=True`
и в списке команд только то, что вы разрешили. Если нет — напишите нейронке: «Добавь проверку `from.id` из `GV_OWNER_ID`,
никакого `shell=True`, команды только из белого списка».

## Шаг 4. Запустите на VPS

Ниже — готовый каркас для Python-бота. Нейронка может предложить свой вариант; суть та же.

**Папка и окружение**

```sh
sudo useradd --system --home /opt/gvbot --shell /usr/sbin/nologin gvbot
sudo mkdir -p /opt/gvbot /etc/gvbot
sudo cp bot.py requirements.txt /opt/gvbot/          # файлы, что написала нейронка
cd /opt/gvbot
sudo python3 -m venv venv
sudo venv/bin/pip install -r requirements.txt
sudo chown -R gvbot:gvbot /opt/gvbot
```

**Файл с секретами `/etc/gvbot/bot.env`** (права `600`, читает только служба):

```sh
GV_API=https://chat.example.com
GV_BOT_TOKEN=gvb_...ваш_токен...
GV_OWNER_ID=ваш-id-из-шага-2
```

```sh
sudo chown root:gvbot /etc/gvbot/bot.env && sudo chmod 640 /etc/gvbot/bot.env
```

### Вариант А. systemd (проще всего)

`/etc/systemd/system/gvbot.service`:

```ini
[Unit]
Description=GusVoice bot
After=network-online.target
Wants=network-online.target

[Service]
User=gvbot
WorkingDirectory=/opt/gvbot
EnvironmentFile=/etc/gvbot/bot.env
ExecStart=/opt/gvbot/venv/bin/python /opt/gvbot/bot.py
Restart=always
RestartSec=5
# Лёгкая защита: бот не видит чужие домашние папки и не получает новые привилегии
NoNewPrivileges=true
ProtectHome=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now gvbot
sudo systemctl status gvbot --no-pager        # должно быть active (running)
journalctl -u gvbot -f                        # логи; выход — Ctrl+C
```

Если бот управляет службами (`/restart nginx`), ему нужно право на `systemctl restart`. Не давайте боту `root`: добавьте
узкое правило sudo, только для нужных команд, в `/etc/sudoers.d/gvbot` (редактировать через `sudo visudo -f /etc/sudoers.d/gvbot`):

```
gvbot ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx, /usr/bin/systemctl restart postgresql
```

и в коде бота вызывать `["sudo", "-n", "/usr/bin/systemctl", "restart", "nginx"]` (список аргументов, без shell).
Попросите нейронку так и сделать.

### Вариант Б. Docker Compose

`Dockerfile`:

```dockerfile
FROM python:3.12.7-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY bot.py .
USER nobody
CMD ["python", "bot.py"]
```

`docker-compose.yml`:

```yaml
services:
  gvbot:
    build: .
    restart: unless-stopped
    env_file: /etc/gvbot/bot.env
```

```sh
docker compose up -d --build
docker compose logs -f gvbot
```

Внутри контейнера бот не увидит службы хоста (`systemctl`). Для панели управления самим VPS берите systemd-вариант; Docker
подходит для уведомлялок, напоминалок и ботов, которые ходят только в сеть.

## Шаг 5. Проверьте

1. В «Мои боты» откройте беседу, напишите `/start`, затем `/help` или `/status`. Бот должен ответить за секунды;
   у вашего сообщения появятся ✓✓ (бот забрал его).
2. **Проверьте защиту.** Пока бот приватный, другой человек даже не сможет открыть с ним беседу. Если когда-нибудь
   сделаете бота «Доступен всем», сначала проверьте с вторым аккаунтом: чужой `/restart nginx` не должен вызвать
   никакой реакции, ни ответа, ни действия.
3. Остановите службу (`sudo systemctl stop gvbot`) и напишите боту: сообщение придёт ему при следующем запуске (события
   хранятся 24 часа).
4. Перезагрузите VPS: бот должен подняться сам.

## Бот на сервере

- Добавить бота на сервер может админ сервера: «Настройки сервера → Интеграции → Боты → Добавить бота». Приватного бота — только вы сами. Дайте боту только нужные права: «Видеть канал» и «Писать», для модерации — «Выгонять/Банить участников».
- **«Читать все сообщения» — только когда без этого никак** (бот-логгер, антиспам). Без галочки бот получает команды `/…`, упоминания `@ник_бота` и ответы на свои сообщения — этого хватает почти всем ботам, и люди спокойнее.
- Проверяйте, **кто** пишет, по `from.id` и ролям (`getChatMember`), а не по нику: у гостя с другого инстанса (`from.instance_domain`) ник может совпасть с местным.
- Бот не видит сообщения других ботов — нейронке не надо писать «защиту от самого себя», но и ждать ответа от другого бота бессмысленно.
- Код должен проверять `chat.type`: `dm` (личка), `channel` (канал сервера), `server` (события входа/выхода), `voice`
  (голосовой канал — для ботов, которые играют звук).

## Типичные ошибки и что ответить нейронке

Скопируйте текст ошибки из логов (`journalctl -u gvbot -n 50 --no-pager`) и отправьте нейронке вместе с фразой из таблицы.
**Токен из логов перед отправкой вырежьте.**

| Что видите | Причина | Что написать нейронке / сделать |
|---|---|---|
| `401 Unauthorized` | Токен неверный, перевыпущен, бот выключен админом, или заголовок не `Authorization: Bot <токен>` | Проверьте токен в `bot.env`; «Перевыпустите токен» и вставьте новый. Нейронке: «Заголовок должен быть строго `Authorization: Bot <токен>`, не Bearer» |
| `403 bots are disabled on this instance` | Администратор выключил боты | Попросите администратора включить («Админ-панель → Боты») |
| `400 chat not found` | Бот пишет в чат, которого нет, или chat_id выдуман | «chat_id бери только из входящего события (`message.chat.id`), строкой. Бот не может писать первым» |
| `400 chat_id: Invalid input: expected string` | id передан числом | «Все id — строки, не приводи к int» |
| `409 Conflict … webhook is active` | У бота задан адрес доставки | «Вызови `deleteWebhook` или перейди на приём событий по адресу» |
| `409 Conflict: terminated by other getUpdates request` или WS закрыт `4009 terminated by other connection` | Запущена вторая копия бота с тем же токеном: потребитель событий один, новый выбивает старый | Остановите лишнюю (`systemctl status`, `docker ps`, старый терминал); один токен — один процесс. Нейронке: «409/4009 — не переподключайся, завершайся с понятным сообщением» |
| `429` | Слишком часто | «Обработай 429: подожди `retry_after` секунд и повтори» |
| Бот отвечает дважды | Повтор доставки (она «хотя бы один раз») | «Отсекай повторы по `update_id`; для отправки задай `client_id` — повтор вернёт то же сообщение» |
| Бот молчит, в логах пусто | Не тот токен/инстанс, служба не запущена, вы пишете не в ту беседу | `systemctl status gvbot`; в «Мои боты» → «Открыть беседу» именно этого бота |
| Бот молчит, в логах `ignored` или ничего | Сработала проверка `from.id`: в `GV_OWNER_ID` не ваш id | Сверьте id из шага 2; нейронке: «Напиши в лог (без токена), чей `from.id` пришёл и что он отклонён» |
| События приходят снова и снова | Не подтверждается `offset` | «После обработки ставь `offset = update_id + 1` и передавай в следующий `getUpdates`» |
| `ModuleNotFoundError` / `Cannot find module` | Зависимости не установлены | `venv/bin/pip install -r requirements.txt`; нейронке: «Дай точные версии зависимостей и команду установки» |
| `Permission denied` при `/restart` | Нет права на `systemctl` | Правило sudo из шага 4; нейронке: «Бот запущен от пользователя gvbot, как дать ему перезапуск только этих служб?» |
| Сообщение длиннее предела | Вывод команды больше 4096 знаков | «Режь длинный вывод на части по 4000 знаков или обрезай до последних 50 строк» |
| `setWebhook … адрес внутренний` | Имя адреса ведёт во внутреннюю сеть | Используйте опрос (по умолчанию), либо попросите админа разрешить внутренние адреса. Сам сервер (`localhost`, `127.0.0.1`, `::1`) закрыт всегда — бот на той же машине работает только опросом или WebSocket |
| Человек пишет боту, а у него «Бот приватный…» / «бот выключен» вместо поля ввода | Бот не «Доступен всем» или выключен админом | Включите «Доступен всем» (если бот проверяет `from.id`) или попросите админа включить бота |

Если нейронка путается — вставьте ей [`bots-llm.md`](bots-llm.md) заново: длинные чаты забывают начало. И пишите ей в
запросе сразу: «Не придумывай методы, которых нет в документации».

## Правила безопасности (кратко)

- Токен — **пароль**: только в `/etc/gvbot/bot.env`, не в коде, не в Git, не в скриншотах и не в чате с нейронкой.
- Бот реагирует только на ваш `from.id`.
- Бот приватный. «Доступен всем» — только если проверка по `from.id` или списку есть и вы её проверили.
- Команды — белый список, текст сообщения не попадает в shell.
- Кнопки — то же самое: нажатие тоже проверяет `from.id`, имя службы из кнопки сверяется со списком, опасное — только через
  «Да / Нет». В данные кнопки (`callback_data`) секретов не класть — их видит клиент человека.
- Подозрение на утечку — «Перевыпустить токен» (старый умирает сразу) и поменяйте значение в `bot.env`, `systemctl restart gvbot`.
