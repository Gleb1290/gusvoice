## 🇷🇺 Что нового

- **Миниатюры прикреплённых картинок.** До отправки картинки показываются превьюшками, а не именами
  файлов: клик открывает просмотр в полный размер со стрелками между ними, крестик убирает лишнюю.
  Раньше десять скриншотов выглядели как десять строк `screenshot-2026-07-20-12-28-27.png`, и понять,
  какой из них лишний, было невозможно
- **Предпросмотр ссылок наконец работает.** В `v0.5.72` он не работал ни для одной ссылки: запрос
  обрывался ещё до соединения, а выглядело это как «сайт без описания» — карточки просто не появлялись
- **Описание больше не дублирует заголовок.** Некоторые сайты (GitHub в их числе) кладут одну и ту же
  фразу в оба поля, и в карточке она печаталась дважды

### Внутреннее

Причина неработающего предпросмотра: свежие версии Node вызывают наш DNS-резолвер в другом режиме и
ждут в ответ список адресов, а мы отдавали один — соединение не устанавливалось никогда. Пропустили
это потому, что все тесты проверяли только блокировку нежелательных адресов и ни один — что разрешённый
адрес доезжает. Добавлен блок проверок на успешный путь, и записано правило: к каждой проверке
«блокируется X» писать парную «пропускается Y». Все неудачи запроса теперь попадают в лог — раньше
молчали обо всём, кроме заблокированных целей, поэтому полный отказ не оставлял ни строчки.

## 🇬🇧 What's new

- **Thumbnails for pending attachments.** Images now show as previews before sending, not filenames:
  click to view full size with arrows between them, the × removes one. Ten screenshots used to be ten
  lines of `screenshot-2026-07-20-12-28-27.png`, with no way to tell which one to drop
- **Link previews actually work now.** In `v0.5.72` they worked for no link at all: the request aborted
  before connecting, and it looked like "the site has no description" — cards simply never appeared
- **Descriptions no longer echo the title.** Some sites (GitHub among them) put the same sentence in
  both fields, and the card printed it twice

### Internal

The preview failure: recent Node versions call our DNS resolver in a different mode and expect a list
of addresses back, while we returned a single one — the connection never established. It slipped
through because every test checked only that unwanted addresses are blocked, and none that an allowed
address gets through. A success-path test block was added, along with the rule: for every "X is
blocked" test, write the paired "Y is allowed". All request failures are now logged — previously
everything except blocked targets was silent, so a total outage left no trace.
