## 🇷🇺 Что нового

Догоняющий релиз к `v0.5.68`: там всплывающие окна чинились наполовину.

- **Меню и поповеры больше не уезжают за экран при увеличенном интерфейсе.** Если в настройках
  стоит масштаб «Крупный» или «Огромный», пикер реакций и контекстные меню вылезали за правую
  и нижнюю кромку — тем сильнее, чем крупнее масштаб. При обычном масштабе всё выглядело
  нормально, поэтому баг долго не находился (#65, #67)
- **Всплывающие слои раскрываются в свободную сторону.** Раньше поповер сползал вдоль кромки
  и мог накрыть кнопку, по которой ты только что нажал. Теперь выбирается сторона, где есть
  место: у кнопки — вверх или вниз, правым или левым краем; у курсора — в свободный квадрант,
  как ведут себя контекстные меню везде (#65, #67)

### Внутреннее
Причина была в том, что настройка масштаба применяет CSS `zoom` к корню документа, а после этого
в приложении сосуществуют две системы координат: `getBoundingClientRect` и вьюпортные единицы
меряют в экранных пикселях, а CSS `left`/`width` и `offsetWidth` — в вёрсточных, которые при
отрисовке ещё раз умножаются на масштаб. Размещение смешивало обе. Перевод координат вынесен
в общий модуль, потолки размеров в стилях переведены на переменные, публикуемые из JS.

## 🇬🇧 What's new

A follow-up to `v0.5.68`, where popups were only half fixed.

- **Menus and popovers no longer slide off-screen at larger interface scales.** With the scale set
  to "Крупный" or "Огромный", the reaction picker and context menus overflowed the right and bottom
  edges — the bigger the scale, the worse. At the default scale everything looked fine, which is
  why this took so long to find (#65, #67)
- **Floating layers now open toward free space.** Previously a popover slid along the edge and could
  cover the very button you clicked. It now picks a side with room: above or below the trigger,
  aligned by its right or left edge; for cursor menus, into the free quadrant, the way context menus
  behave everywhere (#65, #67)

### Internal
The root cause: the interface-scale setting applies CSS `zoom` to the document root, after which two
coordinate systems coexist — `getBoundingClientRect` and viewport units measure in screen pixels,
while CSS `left`/`width` and `offsetWidth` are in layout pixels that get multiplied by the scale at
paint time. Placement mixed the two. Conversion now lives in one shared module, and size ceilings in
CSS moved to variables published from JS.
