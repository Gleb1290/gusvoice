## 🇷🇺 Что нового

- **Трансляция больше не обрывается, когда открываешь личные сообщения.** Раньше стоило стримеру
  заглянуть в ЛС — и показ экрана падал у всех, кто смотрел. Со стороны это выглядело как случайный
  сбой связи: голос-то оставался. Теперь трансляция переживает любую навигацию — переходы по каналам,
  личные сообщения, переключение серверов.
  - Гасится она по-прежнему там, где и должна: когда переходишь в другой голосовой канал или
    выходишь из голоса.
  - Заодно починен родственный случай: системный звук трансляции мог продолжать вещать после того,
    как показ экрана уже остановлен.
  - Касалось только приложения — в браузере трансляция и раньше не падала.

- **Перетаскивание каналов: вернул канал на исходное место — перенос отменяется.** Это единственный
  способ передумать посреди перетаскивания, и он не работал: канал всё равно уезжал туда, куда
  указывала подсказка до этого. Теперь при наведении на собственную строку линия гаснет, и отпускание
  ничего не меняет.

- **Адрес сервера, который не является адресом сервера, теперь честно отклоняется.** Ввод вроде
  `ftp://…` или `mailto:…` раньше молча превращался в какой-то другой адрес, и приложение уходило
  стучаться не туда — а человек видел непонятную сетевую ошибку вместо «проверьте адрес».
  - Отдельно закрыт неприятный случай: строка вида `ваш-сервер.example@чужой-сайт.org` читается
    глазами как адрес вашего сервера, но браузер видит в ней **чужой** хост. Теперь такое не
    принимается вовсе — важно, потому что в это поле вставляют присланный кем-то адрес.
  - Обычный ввод не пострадал: адрес с портом, адрес, скопированный из адресной строки браузера,
    `localhost:3000` и адреса по IP работают как раньше.

## 🇬🇧 What's new

- **Your stream no longer drops when you open direct messages.** Until now, a streamer glancing at
  their DMs killed the screen share for everyone watching. It looked like a random connection
  glitch, since the voice call itself stayed up. The stream now survives any navigation — switching
  channels, opening DMs, changing servers.
  - It still stops where it should: when you move to another voice channel, or leave voice.
  - A related case is fixed too: the stream's system audio could keep broadcasting after the screen
    share had already been stopped.
  - This only affected the app — in the browser the stream never dropped.

- **Dragging channels: putting one back where you picked it up now cancels the move.** That is the
  only way to change your mind mid-drag, and it didn't work — the channel moved to wherever the
  indicator had last pointed. Hovering your own row now clears the indicator, and releasing there
  changes nothing.

- **A server address that isn't a server address is now properly rejected.** Input like `ftp://…` or
  `mailto:…` used to be silently turned into some other address, so the app went knocking on the
  wrong door and you got an obscure network error instead of "check the address".
  - One nastier case is closed as well: a string like `your-server.example@someone-elses-site.org`
    reads to a human as your server, but a browser sees a **different** host in it. That is now
    refused outright — which matters, because this is the field where people paste an address
    someone sent them.
  - Ordinary input is untouched: an address with a port, one copied from the browser's address bar,
    `localhost:3000` and plain IP addresses all work as before.
