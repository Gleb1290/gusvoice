## 🇷🇺 Что нового

Выпуск про надёжность: приложение стало устойчивее к нехватке памяти, а мы наконец снова видим, что
у вас происходит.

- **Починили сбор данных о показе экрана.** Он молчал целые сутки — и мы этого не замечали. Из-за
  прошлого обновления в отчёт попадало испорченное значение, и сервер отбрасывал отчёт **целиком**.
  Выглядело так, будто никто ничего не показывает, хотя показывали все. Теперь испорченная строчка
  теряется сама по себе, а не уносит с собой всё остальное.

- **Приложение стало реже падать при нехватке памяти.** Раньше оно готовило место под каждый кадр
  заново — по тридцать-шестьдесят раз в секунду. Само по себе это не утечка, но делало нас самым
  частым просителем памяти на компьютере, а отказ получает тот, кто просит в неудачный момент.
  Именно поэтому GusVoice падал первым, хотя занимал меньше всех. Теперь место переиспользуется.

- **Стали замечать нехватку памяти заранее.** Мы мерили только оперативную память, а заканчивается
  первой другая — та, что вместе с файлом подкачки. Windows в такие моменты пишет «слишком мало
  виртуальной памяти», и приложения получают отказ. Теперь эта величина видна и нам, и по каждой
  программе отдельно — так что причину будет видно до аварии, а не после.

- **Новый переключатель «Запасной слой качества»** в настройках показа. Он включён, и трогать его не
  нужно. Выключайте, только если показ экрана **вообще перестал запускаться**: значит видеокарте не
  хватило места под второй поток, и это вернёт прежнее поведение.

## 🇬🇧 What's new

A reliability release: the app copes better when memory runs low, and we can finally see what is
happening on your side again.

- **Fixed screen-share data collection.** It had been silent for a whole day without us noticing. A
  corrupted value from the previous update made the server discard the report **entirely**, so it
  looked as if nobody was sharing while everybody was. Now a bad line is dropped on its own instead
  of taking everything else with it.

- **The app crashes less when memory runs low.** It used to reserve room for every single frame anew,
  thirty to sixty times a second. That is not a leak by itself, but it made us the most frequent
  memory requester on the machine — and whoever asks at the wrong moment gets refused. That is why
  GusVoice died first while using the least. The space is now reused.

- **We now notice a memory shortage in advance.** We were measuring only RAM, but the thing that runs
  out first is virtual memory — RAM plus the page file. At such moments Windows reports "too little
  virtual memory" and applications get refused. That figure is now visible to us, per program too, so
  the cause will be visible before a crash rather than after.

- **New switch, "Spare quality layer"**, in the share settings. It is on, and you do not need to touch
  it. Turn it off only if screen sharing **stops starting at all**: that means the graphics card had
  no room for the second stream, and this restores the previous behaviour.
