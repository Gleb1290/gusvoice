# Заметки к релизам · Release notes

Один файл на тег: `docs/release-notes/vX.Y.Z.md`. **Пишется ДО того, как режется тег** — CI читает его
(`scripts/release-notes.ps1`) и подставляет сразу в три места:

| Куда | Что это для пользователя |
|---|---|
| Gitea Release (`build.yaml`) | описание релиза в хоумлаб-репозитории |
| GitHub Release (`publish-public.yaml`) | описание для тех, кто ставит публичный клиент |
| `notes` в `latest.json` (MinIO + GitHub) | **текст в окне «Доступно обновление»** — то, что люди читают чаще всего |

Если файла нет, релиз **не остаётся пустым**: CI соберёт список коммитов и пометит его как автосводку.
Это страховка, а не режим работы — автосводка выдаёт внутренние формулировки вместо человеческих.

## Правила

- **Всегда на двух языках**: русская секция и английская. Инстансы ставят не только русскоязычные.
- Пишем **что изменилось для человека**, а не что поменялось в коде. «Файл из чата теперь можно сохранить
  в свою папку» вместо «`SetResultFilePath` в обработчике `DownloadStarting`».
- Номера issue уместны в конце строки — по ним ищут подробности.
- Ломающие изменения и то, что требует действий (перенастроить, обновить сервер) — отдельным блоком сверху.

## `public/<tag>.md` — накопительная сводка для GitHub-релиза

Обычный `<tag>.md` описывает ОДИН тег: он уезжает в тело Gitea-релиза и в `notes` апдейтера, где
это верно — хоумлаб получает каждый тег подряд.

Паблик живёт иначе: «Лей на паблик» случается раз в несколько десятков тегов (v0.5.65 → v0.6.11 =
26 версий), и человек, скачавший клиент с GitHub, видит одно тело релиза за весь этот промежуток.
Заметки последнего тега там врут по объёму — они описывают последний шаг, а приехало всё.

Поэтому при публикации пишем `public/<tag>.md` — сводку **с прошлой публичной сборки**,
сгруппированную ПО ТЕМАМ, а не по версиям, и применяем её к телу GitHub-релиза:

```bash
gh release edit <tag> --repo Gleb1290/gusvoice --notes-file docs/release-notes/public/<tag>.md
```

⚠️ `scripts/release-notes.ps1` этот каталог НЕ читает (берёт строго `docs/release-notes/<tag>.md`),
так что окно апдейтера показывает заметки последнего тега — это осознанно: сводка на 20 тысяч
символов в маленьком окне «Доступно обновление» нечитаема. Ссылка на полный релиз там есть.

## Шаблон

```markdown
## 🇷🇺 Что нового

- Короткая строка о заметном изменении (#12)
- Ещё одна

### Исправлено
- Что чинили (#34)

## 🇬🇧 What's new

- Short line about a visible change (#12)
- Another one

### Fixed
- What was fixed (#34)
```
