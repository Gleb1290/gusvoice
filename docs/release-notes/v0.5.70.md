## 🇷🇺 Что нового

- **Предпросмотр ссылок.** Под сообщением со ссылкой появляется карточка: сайт, заголовок и описание
  страницы. Отключается в Настройки → Внешний вид → Ссылки (#64)
- **Настройки ссылок собраны в одном месте.** Там же — переключатель предупреждения о переходе на
  сторонний сайт и кнопка «забыть доверенных отправителей», если раньше нажал «больше не спрашивать»
  и передумал (#63, #64)

### Почему в карточке нет картинки

Это решение, а не недоделка. Показать картинку со стороннего сайта — значит заставить браузер
**каждого**, кто открыл канал, сходить на этот сайт: тот узнает ваш адрес и факт чтения сообщения.
Ровно такую дыру уже закрывали для вложений. Заголовок и описание забирает сервер, поэтому
сторонний сайт видит один запрос от сервера, а не от всех читателей. Картинки появятся, когда
сервер научится складывать их к себе.

### Внутреннее

Запросы наружу идут через отдельный защищённый клиент: адрес проверяется **до** подключения и
заново на каждом перенаправлении, приватные диапазоны (домашняя сеть, loopback, адреса метаданных
облака) отбиваются. Иначе любой участник, отправив в чат ссылку на внутренний адрес, заставил бы
сервер сходить туда и вернуть ответ. Фильтр покрыт 67 тестами; тесты добавлены в CI-гейт — теперь
push не проходит, если они падают.

## 🇬🇧 What's new

- **Link previews.** Messages with links now show a card underneath: site, page title and description.
  Toggle it off in Settings → Appearance → Links (#64)
- **Link settings in one place.** The same section now holds the "warn before leaving" toggle and a
  button to forget trusted senders, if you clicked "don't ask again" and changed your mind (#63, #64)

### Why the card has no image

That's a decision, not an omission. Rendering a remote image makes **every** reader's browser fetch it
from that third-party site, revealing their address and the fact they read the message. We closed the
same hole for attachments. Title and description are fetched by the server instead, so the third party
sees one request from the server rather than one per reader. Images will come once the server caches
them itself.

### Internal

Outbound requests go through a dedicated hardened client: the address is validated **before** the
connection and again on every redirect, with private ranges (home network, loopback, cloud metadata)
rejected. Otherwise any member could post a link to an internal address and make the server fetch it.
The filter is covered by 67 tests, now wired into the CI gate — a push fails if they do.
