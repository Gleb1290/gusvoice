# Входящие вебхуки

> English version: [webhooks.md](webhooks.md)

Входящий вебхук — секретный адрес, по которому внешняя программа (сборка CI, мониторинг, свой скрипт) пишет
сообщения в **текстовый канал** GusVoice без входа в аккаунт. Формат запроса повторяет Discord «Execute Webhook»,
поэтому большинству готовых интеграций для Discord достаточно поменять адрес (что не переносится — в разделе
[Отличия от Discord](#отличия-от-discord)).

Сообщения вебхука подписаны его именем и аватаром, у имени стоит пометка **ВЕБХУК**. Профиля у вебхука нет,
написать ему в личные нельзя.

---

## Как завести вебхук

**Кто может:** тот, у кого есть право **«Управление вебхуками»** на этот канал (владелец сервера,
администраторы или роль с этим правом; переопределения прав канала учитываются). У `@everyone` по умолчанию
этого права нет.

**Где:**

- **Настройки канала → Вебхуки** (карандаш у текстового канала; у кого есть «Управление вебхуками», но нет
  «Управления каналами», — пункт «Вебхуки канала» в контекстном меню канала).
- **Настройки сервера → Интеграции** — все вебхуки сервера в каналах, где у вас есть и «Просмотр канала», и
  «Управление вебхуками», плюс «Новый вебхук» с выбором канала.

Вебхук бывает только у **текстового** канала. На канал — не больше **15** вебхуков.

**Адрес показывается один раз.** Сразу после «Новый вебхук» редактор показывает полный адрес и кнопку
«Скопировать». На сервере хранится только SHA-256-отпечаток токена, поэтому показать адрес позже нельзя.
Потеряли — нажмите **«Новый адрес»**: выдаётся новый токен, старый адрес перестаёт работать сразу.

В редакторе также можно:

- переименовать вебхук (1–80 знаков) — это имя автора его сообщений по умолчанию;
- загрузить аватар (PNG, JPEG, WEBP или GIF, до 512 КБ) или убрать его;
- перенести в другой текстовый канал того же сервера (нужно право на оба канала); адрес не меняется;
- **«Удалить вебхук»** — адрес умирает сразу, уже написанные сообщения остаются в канале.

Новое имя или аватар историю не переписывают: каждое сообщение хранит имя и аватар на момент отправки.
Создание, правка, новый адрес и удаление попадают в журнал действий сервера.

## Запрос

```
POST https://api.example.com/api/webhooks/<id>/<token>
```

- `api.example.com` — адрес **API** вашего инстанса (не адрес веб-клиента). Проще всего скопировать адрес из
  редактора вебхука — он уже полный.
- `<id>` — id вебхука (UUID), `<token>` — секрет из 43 знаков (`A–Z a–z 0–9 _ -`).
- Заголовок `Authorization` не нужен: токен в адресе и есть пропуск.
- Тело: `application/json` (до **64 КБ**) или `multipart/form-data` (чтобы приложить файлы).
- Параметр `wait`:
  - нет или `wait=false` → **204 No Content**;
  - `wait=true` → **200 OK** и созданное сообщение в JSON (см. [Ответы](#ответы-и-ошибки));
  - принимаются только строки `true` и `false`; `wait=1` — это 400.

### Тело JSON

Все поля необязательны, но в сообщении должно остаться хотя бы одно из: непустой `content`, непустая
карточка или файл. Неизвестные поля (`tts`, `flags`, `components`, `thread_name`, `poll`…) молча
отбрасываются — программы для Discord на них не спотыкаются.

| Поле | Тип | Пределы и поведение |
|---|---|---|
| `content` | строка | До **4096** знаков (единиц UTF-16). Пробелы по краям обрезаются. Рисуется нашим подмножеством Markdown — так же, как сообщение человека. |
| `username` | строка | Имя автора только для этого сообщения. После обрезки пробелов — 1–80 знаков, иначе **молча игнорируется** и берётся имя вебхука (строка длиннее 320 знаков — 400). |
| `avatar_url` | строка | Аватар только для этого сообщения — **только** если адрес ведёт в медиа-хранилище этого же инстанса (например, уже загруженный здесь аватар или вложение). Любой другой адрес молча игнорируется: чужие картинки в ленту не грузятся (это был бы пиксель слежения). До 2048 знаков. |
| `embeds` | массив | До **10** карточек, см. [Карточки](#карточки-embeds). |
| `allowed_mentions` | объект | Сужает, кого сообщение может позвать, см. [Упоминания](#упоминания). |

### Карточки (embeds)

Объект карточки — как Embed Object у Discord. Принимаемые поля и пределы:

| Поле | Предел | Заметки |
|---|---|---|
| `title` | 256 | Сводится в одну строку. |
| `url` | 2048 | Делает заголовок ссылкой. Только `http://` / `https://`, иначе выбрасывается. |
| `description` | 4096 | Наш Markdown, как в обычном сообщении. |
| `color` | целое | `0x000000`–`0xFFFFFF` (в JSON — десятичное, например `3066993`). Вне диапазона — карточка без цветной полосы. Строка вроде `"#2ecc71"` — **400**. |
| `timestamp` | 64 | Любая дата, которую понимает `Date.parse` (лучше ISO 8601); сохраняется в ISO. Непонятная — выбрасывается. |
| `fields[]` | до 25 | Каждое `{ "name": ≤256, "value": ≤1024, "inline": bool }`. Ключи `name` и `value` обязательны; поле, где оба пустые, выбрасывается. |
| `author` | | `{ "name": ≤256 (обязательно), "url": ≤2048, "icon_url": ≤2048 }` |
| `footer` | | `{ "text": ≤2048 (обязательно), "icon_url": ≤2048 }` |
| `image` | | `{ "url": ≤2048 }` |
| `thumbnail` | | `{ "url": ≤2048 }` |

- **Суммарный текст** всех карточек сообщения (`title` + `description` + имена и значения полей +
  `footer.text` + `author.name`) — не больше **6000** знаков, иначе 400.
- Прочие ключи карточки Discord (`video`, `provider`, `type`) игнорируются. Пустые карточки выбрасываются.
- Карточка рисуется под сообщением: цветная полоса, заголовок-ссылка, поля (`inline` — в ряд), подвал и время.
  Клик по подписанной ссылке (заголовок, имя автора) открывает окно «Открыть ссылку?» с полным адресом —
  подпись может не совпадать с адресом.

**Картинки в карточках.** GusVoice никогда не заставляет клиент читателя грузить картинку с чужого сервера.

| Адрес в `image.url` / `thumbnail.url` | Что будет |
|---|---|
| `attachment://<имя_файла>` | Файл с этим именем из того же multipart-запроса — показывается картинкой. |
| Адрес в медиа-хранилище этого инстанса | Показывается картинкой. |
| Любой другой `https://` | **Не грузится.** Показывается обычной ссылкой под карточкой. |
| `http://`, `data:` и прочее | Выбрасывается. |

`author.icon_url` и `footer.icon_url` показываются только для `attachment://` и адресов нашего хранилища,
прочие выбрасываются (ссылкой не показываются).

**Старые клиенты.** Если у сообщения есть карточки, но нет `content`, сервер дополнительно кладёт в `content`
текстовую версию карточек (цитатой), чтобы старые клиенты GusVoice что-то показали. Нынешние клиенты рисуют
карточки и этот текст скрывают. В ответе `wait=true` у такого сообщения `"embedsFallback": true`.

### Файлы (multipart/form-data)

Отправьте `multipart/form-data` с частями:

- **`payload_json`** — то же JSON-тело, что выше, строкой (карточки и `allowed_mentions` — только так). Если
  `payload_json` есть, остальные текстовые части игнорируются.
- *или*, без `payload_json`, простые текстовые части **`content`**, **`username`**, **`avatar_url`**.
- **файлы** — в частях `files[0]` … `files[9]` (как у Discord); старые имена `file`, `file1`, `file2`… тоже
  принимаются. Файл в части с другим именем → **400**.

Пределы:

| | |
|---|---|
| Файлов в сообщении | **10** (11-й → 413 `reach files limit`) |
| Размер файла | **25 МБ** (больше → 413) |
| Текстовых частей | 8, каждая до 64 КБ |
| Запрещённые типы | **SVG и HTML** (`image/svg+xml`, `text/html`, `application/xhtml+xml` или расширения `.svg`, `.html`, `.htm`, `.xhtml`) → **415** |
| Частота загрузок | 15 файлов в минуту на вебхук (вдобавок к пределу сообщений ниже) |

Файлы становятся обычными вложениями сообщения. Имя файла и `Content-Type` части сохраняются, поэтому
указывайте верный тип (`curl -F "files[0]=@chart.png;type=image/png"`); картинки показываются превью, как
любое вложение. Чтобы показать загруженную картинку в карточке, сошлитесь на неё как `attachment://<имя_файла>` —
имя должно совпадать с именем загруженного файла точь-в-точь (с учётом регистра).

Предел тела 64 КБ действует только для JSON; для multipart — пределы на файл и часть из таблицы. Обратный
прокси перед инстансом может ставить свой предел на загрузку.

### Упоминания

Упоминания в GusVoice — обычный текст: человек — по **логину** (`@alice`), роль — по **названию**
(`@Модераторы`), плюс `@everyone` и `@here`. Синтаксис Discord с id (`<@123>`, `<@&456>`, `<#789>`) не
разбирается и показывается как есть.

**По умолчанию — как у Discord:** без `allowed_mentions` сообщение вебхука зовёт всех, кого упоминает:
`@everyone`, `@here`, любые роли (даже без галки «Упоминаемая») и людей. Вебхук не ограничен правом
«Упоминать @everyone, @here и все роли» того, кто его завёл: у кого есть адрес, тот может позвать весь канал.
Для автоматических сообщений правильно слать `"allowed_mentions": { "parse": [] }`.

`allowed_mentions` сужает умолчание:

| Ключ | Смысл |
|---|---|
| `parse` | Какие виды брать из текста: `"everyone"` (это и `@everyone`, и `@here`), `"roles"`, `"users"`. До 8 элементов. |
| `roles` | Массив **id** ролей, которые можно звать (действует, если `"roles"` нет в `parse`). До 100. |
| `users` | Массив **id** людей, которых можно звать (действует, если `"users"` нет в `parse`). До 100. |

Примеры:

- `{ "parse": [] }` — никого не звать.
- `{ "parse": ["users"] }` — только людей; `@everyone`, `@here` и роли молчат.
- `{ "parse": [], "roles": ["<id роли>"] }` — только эту роль.

Запрещённое упоминание выглядит для читателя так же (`@everyone`), но сервер вставляет после `@` пробел
нулевой ширины — подсветки, звука и пуша нет. Упоминания **внутри карточек никого не зовут**. Упомянутые
получают обычный пуш об упоминании.

## Ответы и ошибки

**Успех**

- `204 No Content` — сообщение отправлено (по умолчанию).
- `200 OK` с `?wait=true` — объект сообщения GusVoice, например:

```json
{
  "id": "7d1e2c4a-…",
  "channelId": "2b9f0e61-…",
  "content": "Build #42 passed",
  "createdAt": "2026-10-26T07:05:57.583Z",
  "webhookId": "9a4c7b13-…",
  "attachments": [{ "url": "https://…", "name": "chart.png", "contentType": "image/png", "size": 110 }],
  "embeds": [{ "title": "Chart", "image": { "url": "https://…" } }],
  "author": { "id": "…", "username": "webhook:9a4c7b13-…", "displayName": "CI bot", "avatarUrl": null }
}
```

Это формат сообщений GusVoice (camelCase), **а не** объект сообщения Discord. `attachments`, `embeds`,
`embedsFallback` есть только когда они не пустые.

**Ошибки** — тело всегда JSON `{ "error": "<текст>" }`; у ошибок проверки есть ещё `details` (список проблем с
`path`). Текст написан для человека (часто по-русски) и может меняться — решайте по **коду ответа**, а не по
тексту.

| Код | Когда |
|---|---|
| 400 | Кривой JSON; поле длиннее предела или не того типа (`details[].path` подскажет какое; слишком длинный `content`: `"Слишком длинное сообщение: не больше 4096 знаков"`); текст карточек больше 6000; пустое сообщение (`"пустое сообщение: нужен content, embeds или файл"`); `wait` не `true`/`false`; `payload_json` — не JSON; файл не в части `files[n]`/`file`. |
| 404 | `{"error":"unknown webhook"}` — неверный id, неверный токен, токен кривой формы, вебхук удалён, канал удалён или больше не текстовый. Все эти случаи нарочно неотличимы. |
| 413 | JSON больше 64 КБ (`Request body is too large`); файл больше 25 МБ; больше 10 файлов (`reach files limit`); слишком много частей multipart. |
| 415 | Тип тела не `application/json` / `multipart/form-data` (`application/x-www-form-urlencoded` не поддерживается); запрещённый тип файла (SVG/HTML). |
| 429 | Предел частоты, см. ниже. Тело `{"error":"…","retry_after":<секунды>}`, заголовок `Retry-After: <секунды>`. |
| 503 | Прислали файлы, а медиа-хранилище у инстанса не настроено. |

Часть проверок идёт до проверки токена (размер тела, синтаксис JSON, неподдерживаемый тип), поэтому запрос
с неверным токеном может получить 400/413/415, а не 404.

**Пределы частоты** (фиксированные окна по минуте):

- **30 запросов в минуту на вебхук.** Считается каждый запрос с верным адресом, в том числе отклонённый с 400.
- **120 запросов в минуту с одного IP** на все адреса вебхуков — считается раньше всего остального.
- **15 загруженных файлов в минуту на вебхук.** Если предел кончился посреди запроса с несколькими файлами,
  запрос получает 429, и сообщение не публикуется.

На 429 подождите `retry_after` секунд (целое число, у Discord — дробное) и повторите. Заголовков
`X-RateLimit-*` нет. Страницы чужих сайтов в браузере вебхук вызвать не могут (CORS), а заголовок
`Retry-After` браузерному коду не виден — вебхуки рассчитаны на серверы и скрипты.

## Примеры

Храните адрес в секрете (переменная окружения, секрет CI), не в репозитории. Ниже это
`$WEBHOOK_URL` = `https://api.example.com/api/webhooks/<id>/<token>`.

### curl — текст

```sh
curl -sS -X POST "$WEBHOOK_URL" \
  -H 'Content-Type: application/json' \
  -d '{"content": "Выкатка завершена", "allowed_mentions": {"parse": []}}'
```

### curl — карточка (и получить сообщение в ответ)

```sh
curl -sS -X POST "$WEBHOOK_URL?wait=true" \
  -H 'Content-Type: application/json' \
  -d '{
    "username": "CI",
    "embeds": [{
      "title": "Сборка #42 прошла",
      "url": "https://ci.example.com/builds/42",
      "description": "Все **12** проверок зелёные",
      "color": 3066993,
      "fields": [
        { "name": "Ветка", "value": "main", "inline": true },
        { "name": "Время", "value": "4 мин 12 с", "inline": true }
      ],
      "footer": { "text": "example-ci" },
      "timestamp": "2026-10-26T07:00:00Z"
    }],
    "allowed_mentions": { "parse": [] }
  }'
```

### curl — файл (multipart)

```sh
curl -sS -X POST "$WEBHOOK_URL" \
  -F 'payload_json={"content": "Ночной отчёт", "embeds": [{"title": "График нагрузки", "image": {"url": "attachment://chart.png"}}]}' \
  -F 'files[0]=@chart.png;type=image/png' \
  -F 'files[1]=@build.log;type=text/plain'
```

Без карточек текст можно передать простой частью: `-F 'content=Ночной отчёт' -F 'files[0]=@build.log'`.

### Python (requests)

```python
import json
import os

import requests

url = os.environ["WEBHOOK_URL"]

# Текст + карточка
r = requests.post(url, json={
    "content": "Бэкап готов",
    "embeds": [{"title": "db-backup", "description": "Размер: 1,2 ГБ", "color": 0x2ECC71}],
    "allowed_mentions": {"parse": []},
}, timeout=10)
r.raise_for_status()  # 204

# Файл
with open("report.pdf", "rb") as f:
    r = requests.post(
        url,
        data={"payload_json": json.dumps({"content": "Недельный отчёт"})},
        files={"files[0]": ("report.pdf", f, "application/pdf")},
        timeout=60,
    )
if r.status_code == 429:
    print("слишком часто, повторить через", r.json()["retry_after"], "с")
r.raise_for_status()
```

### Node.js (18+, встроенный fetch)

```js
import { readFile } from 'node:fs/promises';

const url = process.env.WEBHOOK_URL;

// Текст
let res = await fetch(url, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ content: 'Сервис снова работает', allowed_mentions: { parse: [] } }),
});
if (!res.ok) throw new Error(`${res.status} ${await res.text()}`);

// Файл + карточка, которая его показывает
const form = new FormData();
form.append('payload_json', JSON.stringify({
  embeds: [{ title: 'Процессор за сутки', image: { url: 'attachment://cpu.png' } }],
}));
form.append('files[0]', new Blob([await readFile('cpu.png')], { type: 'image/png' }), 'cpu.png');
res = await fetch(`${url}?wait=true`, { method: 'POST', body: form });
console.log(res.status, await res.json());
```

### GitHub Actions

Сохраните адрес секретом репозитория `GUSVOICE_WEBHOOK_URL` и добавьте шаг:

```yaml
- name: Notify GusVoice
  if: always()
  env:
    WEBHOOK_URL: ${{ secrets.GUSVOICE_WEBHOOK_URL }}
    STATUS: ${{ job.status }}
  run: |
    color=15158332; [ "$STATUS" = "success" ] && color=3066993
    jq -n \
      --arg title "$GITHUB_REPOSITORY: $GITHUB_WORKFLOW — $STATUS" \
      --arg url "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID" \
      --arg ref "$GITHUB_REF_NAME" --arg sha "${GITHUB_SHA::7}" --arg actor "$GITHUB_ACTOR" \
      --argjson color "$color" \
      '{embeds: [{title: $title, url: $url, color: $color,
                  fields: [{name: "Ветка", value: $ref, inline: true},
                           {name: "Коммит", value: $sha, inline: true},
                           {name: "Кто", value: $actor, inline: true}]}],
        allowed_mentions: {parse: []}}' \
    | curl -sS --fail-with-body -X POST "$WEBHOOK_URL" -H 'Content-Type: application/json' --data-binary @-
```

JSON собирается `jq`, чтобы кавычки и переводы строк в названии ветки или тексте коммита его не ломали.

Собственные вебхуки репозитория GitHub (Settings → Webhooks) шлют события в формате GitHub, который GusVoice
не понимает, — используйте шаг Actions, как выше.

## Отличия от Discord

Совпадает:

- `POST /api/webhooks/{id}/{token}`, `?wait=true` (200 + сообщение) / 204 без него.
- `content`, `username`, `embeds` (Embed Object Discord, те же пределы длины, 10 на сообщение, 6000 суммарно),
  `allowed_mentions` (`parse`, `roles`, `users`) с умолчанием Discord (зовутся все упомянутые).
- `multipart/form-data` с `payload_json` + `files[n]` (и старые `file`/`fileN`), `attachment://имя` в карточках.
- 15 вебхуков на канал, около 30 сообщений в минуту на вебхук, неизвестные поля игнорируются.

Иначе или нет:

| Discord | GusVoice |
|---|---|
| `avatar_url` с любой картинкой | Только картинка из хранилища этого инстанса; прочие игнорируются. |
| Чужие картинки в карточках проксируются и показываются | Не грузятся: `image`/`thumbnail` становятся ссылкой, чужой `icon_url` выбрасывается. |
| `username` длиннее 80 → 400 | Игнорируется, берётся имя вебхука. |
| Упоминания `<@id>`, `<@&id>`, каналы `<#id>`, время `<t:…>`, свои эмодзи | Обычный текст; упоминания — `@логин` / `@НазваниеРоли`. |
| Подписанные ссылки `[текст](url)` в тексте | Не поддерживаются (ссылка, которая врёт про адрес, — инструмент фишинга); пишите сам адрес. Кликабельный заголовок — через `url` карточки. |
| `wait=1`, `wait=True` | Только `true` / `false`. |
| `application/x-www-form-urlencoded` | 415. |
| Заголовки `X-RateLimit-*`, дробный `retry_after` | Только `Retry-After` и целый `retry_after`. |
| Тело ошибки `{ "code", "message", "errors" }` | `{ "error", "details" }`. |
| Объект сообщения в snake_case | Объект сообщения GusVoice (camelCase). |
| `GET /webhooks/{id}/{token}`; правка/удаление сообщений через `/messages/{message_id}`; `thread_id` / `thread_name`; `tts`, `components`, `flags`, `poll` | Нет (`tts`, `components`… игнорируются, остальные маршруты отвечают 404). |
| Совместимые адреса `/slack` и `/github` | Нет. |
| Управление вебхуками токеном бота | Только из приложения (см. ниже). |

Если готовая интеграция шлёт только `content`/`embeds` в JSON или `payload_json` + `files[n]`, достаточно
поменять адрес.

## Управление вебхуками через API

Этими маршрутами пользуется приложение; нужны вход пользователя (`Authorization: Bearer <сессия>`) и право
«Управление вебхуками» на канал. Перечислены для полноты — обычно хватает интерфейса.

| Метод и путь | Что делает |
|---|---|
| `GET /api/channels/{channelId}/webhooks` | Вебхуки канала. |
| `GET /api/servers/{serverId}/webhooks` | Вебхуки сервера (каналы, где можно смотреть и управлять). |
| `POST /api/channels/{channelId}/webhooks` `{ "name": "…" }` | Создать; в ответе (201) есть `token` — единственный раз. |
| `PATCH /api/webhooks/{id}` `{ "name"?, "channelId"?, "avatarUrl"?: null }` | Переименовать, перенести в другой текстовый канал, убрать аватар. |
| `POST /api/webhooks/{id}/avatar` (multipart `file`) | Поставить аватар (PNG/JPEG/WEBP/GIF, ≤ 512 КБ). |
| `POST /api/webhooks/{id}/token` | Выдать новый токен (возвращается один раз); старый адрес перестаёт работать. |
| `DELETE /api/webhooks/{id}` | Удалить (204); написанные сообщения остаются. |

## Безопасность

- **Адрес — это пароль.** У кого он есть, тот пишет в канал от имени вебхука и по умолчанию может позвать
  `@everyone`. Храните его в хранилище секретов (секреты CI, переменные окружения, vault); не коммитьте, не
  пересылайте в чатах, не вставляйте в веб-страницы и мобильные приложения.
- Сервер хранит только SHA-256-отпечаток токена и сравнивает его за постоянное время; неверный id и неверный
  токен дают одинаковый 404, по ответу нельзя понять, какие вебхуки существуют.
- Шлите `"allowed_mentions": { "parse": [] }`, если сообщению не нужно звать людей.
- **Если адрес утёк:** откройте вебхук (настройки канала → Вебхуки или настройки сервера → Интеграции) и нажмите
  **«Новый адрес»** — старый перестанет работать сразу; новый пропишите в интеграцию. Вебхук больше не нужен —
  удалите его. Уже написанные сообщения модераторы удаляют как любые другие, а журнал действий покажет, кто
  заводил вебхук и перевыпускал адрес.
- Сообщения вебхука всегда помечены **ВЕБХУК** — выдать себя за участника он не может, даже подставив в
  `username` чужое имя.
